#     run=N | reason

# The reason is what a reader needs to know that the fall was a decision and not a loss: what
# fell, why, and which ticket owns getting it back. talk/fall_check.py validates this file the
# way talk/verify-all.sh validates talk/verify-exclusions.txt: a malformed line is a fault, a
# line with no reason is a fault, and a line naming a run talk/truth.log does not record is a
# fault, because an escape hatch nobody can check against the log is a hole.
#
# THE KEY IS NOT GLOBALLY UNIQUE, and nothing here can make it so (ticket 59's design, named
# 2026-09-09 by ticket 108's review, F7). `N` is GITHUB_RUN_NUMBER. Re-running a workflow reuses
# the number, and deleting and recreating the workflow restarts it at 1, so two different
# observations could one day answer to the same `run=`. Today talk/truth.log's numbers are
# strictly increasing and every one of them is distinct, which is checkable and is checked; the
# day that stops being true, a reason accepted here would attach to whichever line the log
# carries. Nothing keys off the run number except this file and the log itself.
#

# 2026-09-09). The recorded log carries fifteen older transitions with an unaccounted fall, the

# fifteen now would be the estate telling itself a story. The count is printed on every run by
# verify/a-fall-blocks/verify-a-fall-blocks.sh instead, so the history is a number that moves
# rather than a sentence that rots. Only the transition ENDING AT THE RUN BEING RECORDED is
# graded, because that is the only one a run can still do something about (ticket 55: every red
# is real, explained and finishable; ticket 108 for which transition that is).
