# 12 — The graph schema and validation

**What to build:** Formalises the minimal schema the skeleton seeded. The organisation as a typed knowledge graph:
components, edges, overlays, and the Wardley value-chain spine.

**Special-category data has no schema slot.** Article 9 compliance is an impossibility of
representation, not a validation rule that could later be relaxed. People's structural edges are in
the graph; behavioural observations live in a gated overlay.

Do not start before ticket 07 lands — the skeleton's schema is the seed, and racing it produces two
schemas.

## Built (2026-08-05)

`twin/schema.py`, plus `Graph`/`BehaviouralOverlay` in `twin/model.py` and `twin graph` / `twin validate`.

- **The schemas are closed.** A key that is not declared is rejected. That is what makes "no schema
  slot" true rather than aspirational: `no_special_category_slot` is not a rule that could be relaxed,
  it is the absence of anywhere to put the data. The 23 Article 9 names exist only so the refusal can
  say *which* category was attempted; the closure is the guard, and both are declared in the manifest so
  neither can shrink quietly.
- Refusal reaches arbitrary depth, including inside the free-form containers (`provenance` takes any
  mapping — the obvious place to smuggle one), and respelling (`health-status`, `HEALTH`) does not help.
- **Typed edges, one home each.** The Wardley spine is authored as a component's `needs` because a value
  chain should read as one; person edges (`maintains`/`knows`/`owns`) are first-class objects because
  they are not a chain. Both arrive in the graph as the same typed edge, and authoring a structural edge
  the second way is refused. `causal` is not in the vocabulary yet — build ticket 17 extends it.
- **The behavioural overlay is a separate unit, not a flag.** `Overlay.load` has no route to it.
  Loading it requires naming it, a DPIA, a lawful basis, a retention period and `advisory_only: true`
  (Article 22). Observations are cohort-level because there is no `person` field — "aggregate over
  individual" as structure rather than guidance. Detaching it is `git rm` and everything else still
  loads, which a test asserts.
- Validated at load, and `twin validate` is the gate before a commit. Nothing here writes model files —
  authors write text — so "validated on write" means validated where the model enters the system.
- The graph fixture is generated, never committed: `twin graph` emits it from the deterministic fixture
  repository and CI runs it through `twin/demo.sh`.

## Review round (2026-08-06)

Three reviews — correctness, honesty, mutation — ran against the first pass. What they found:

- **The Article 9 guard checked keys and not values.** A cohort called `staff-on-long-term-sickness`
  with a metric called `health-status` validated, loaded, and sat in the gated behavioural unit — the
  exact place the whole story is about. Now screened as a value too, and **the claim is narrowed to what
  is actually true**: the closed schema is a guarantee about *fields*; the value screen is a **net, not
  a proof**, because `cohort` and `metric` are free identifiers and no word list can be complete. The
  manifest, `twin/schema.py` and the README all say so.
- **Meta files were never validated.** `world-meta` and `overlay-meta` had schemas and no call site, so
  Article 9 data could sit in `meta.yaml` while `twin validate` printed PASS. A directory nothing loads
  is now refused rather than ignored, for the same reason.
- **World-layer `needs` was dropped from the graph**, so the shared value chain — the thing the spine is
  for — was invisible in every graph artefact.
- **The prose leg of the direction rule was case-sensitive**, so `Netflix` walked past a guard that
  catches `netflix`. The planted violation in the fixture was lowercase, which is why it stayed green.
- **A mutation survived**: deleting the closed-schema check left `twin verify` green, because the
  invariant only ever planted Article 9 *names*, which the denylist catches first. The closure is now
  asserted directly.
- The graph artefact was outside the emitted set, so no per-artefact invariant covered it. It is in now.

Not built: `Asset`/`DataAsset` and `Response`/`Control` from decision ticket 07's entity list, and the
causal edge type. Both are named there and neither is here, which is why domain-model AC 1 stays unticked.
