##### PR #16287: fix(cli): surface GeneratingPolicy CEL errors when metadata.uid is missing
merged_at: 2026-07-08T08:01:44Z  base: main
## Summary

Fixes #16282 — `kyverno apply` now reports CEL evaluation failures for `GeneratingPolicy` instead of silent all-zero output when test resources omit `metadata.uid`.

## Explanation

CLI test fixtures often omit `metadata.uid` (the API server assigns it in real clusters). If a policy reads `object.metadata.uid`, the CLI used to show `pass: 0, fail: 0, warn: 0, error: 0, skip: 0` with exit 0 and no message — the same as “policy didn’t match.” This PR fixes that by counting `error`/`skip`/`warn` for GPOL, printing generate errors in apply output, and fixing `kyverno test` for Generation rules with no generated resources.

**Type:** bug fix (existing behavior correction)
