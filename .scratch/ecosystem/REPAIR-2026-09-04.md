The diagnosis behind that number split the rows three ways: **8 regressions this build caused**,

## 1. `verify/provenance/provenance.py` — KeyError on a field ticket 78 deleted

**Cause.** Ticket 78 removed `signed` from every proposal `wargamer.py` emits, on the ground that a
signature is a property of the *commit* — put there by `propose-tier.yml`'s gitsign step and read
back out of Rekor — and never a literal a proposal may claim about itself. `provenance.py` still
read `pr["signed"]` in two places: the PR link of the chain (:110) and the selfcheck assertion
(:219). Both died with `KeyError: 'signed'`, unmasked, because nothing on this machine's PATH was
missing to hide it behind a could-not-look.

**Fix.** Dropped `"signed": pr["signed"]` from the PR link dict, with the reason in a comment, and
replaced `assert pr["signed"] is True and "Rekor" in pr["identity"]` with the pair
`assert "signed" not in pr` / `assert "Rekor" in pr["identity"]` — the same assertion
`wargamer.py:483-484` now makes about its own output. The chain claims the identity **mechanism**
and never a signature the proposal does not have.

Ticket 76's `selfcheck_absent` leg needed no change: it reported the fault correctly.

**Proof.** `bash verify/provenance/verify-provenance.sh` → exit 3, last line:

```
SKIP: the offline proof holds; 2 live tail(s) could not look, so this run did not observe the
claim above -- no rekor-cli here to query the transparency log, so the commit link was read from
the committed chain only, never confirmed against Rekor (gitsign is installed [gitsign version
0.17.1], but it signs, it does not query); no SPIRE server on kind-driftwood, so no live SVID was
seen (the committed manifests are asserted offline in step 1)
```

Exit 3 is the declared outcome for this script (`never: no rekor-cli here|kind-driftwood is not
reachable`). Before the fix the same command exited 1 on
`FAIL: selfcheck: ... exited 1 (want 3) ... FAIL: provenance chain selfcheck failed`.

## 3. `verify/e2e/step3_band.py` — the proposer is right and the step was stale

**Cause.** Ticket 78 gave `tier_pr.py` a tighten-only clamp: the party's folded tier is never
written when it does not tighten what the governed Namespace declares today. driftwood has
declared `posture.acme.io/tier: isolated` — the **top** rung of `cage.ORDER`
(`baseline < restricted < quarantine < isolated`) — since ticket 26, long before this build. The
priced line in this fixture selects `restricted`, which is looser. So the proposer holds, and the
step's `if p.get("landed") != "dry-run": fail(...)` could never be satisfied again.
`tier_pr.py`'s own selfcheck (lines ~899-912) asserts exactly that behaviour: *a per-line crossing
on a party declared isolated must be HELD, not landed*, with no `landed`, no `error` and no branch.

**Decision (delegated): option (b).** The brief offered (a) drive the step with a party whose
governed Namespace declares a tier the priced line actually tightens, or (b) keep driftwood and
re-point the step at the tighten-only outcome.

(a) is not available. The step picks its party by "the first adopter that publishes a
`selection-policy/` package with a VERSION", because the whole point of the step is that the
**adopter's own versioned package** makes the selection (ADR-0021) and `platform/graded/cage.py`
only cross-checks it. driftwood is the only party in the estate that publishes one — checked
across all eight units. The only other way to reach (a) would be to loosen driftwood's real
declaration off `isolated` so a probe could tighten it, which is weakening the estate's posture to
keep a test green: the one thing this gate exists to refuse. `tier_pr.py` was not touched.

So (b). The observable NORTH-STAR §4 fact the step now grades is: a priced line crossing the band
selects a different tier through the adopter's own package, and the proposer **HOLDS** rather than
proposing a loosening — writing nothing, branching nothing, opening nothing.

**Fix.** A new pure function `judge_held(landed, org, line_tier, order)` returns `None` or the
reason, and asserts the held document's shape: non-empty output; no `landed`; no `error`;
`held == "tighten-only"`; `proposal_kind == "pull_request"`; both tiers on the ladder;
`party_tier` does **not** tighten `current_tier` (a hold that *should* have landed is caught);
`line_tier` is the tier this step priced; a non-empty `why`. The three assertions that already bit
still bite: the declaration is unchanged on disk, the pod manifest is untouched, and — new — no
branch exists in the throwaway copy.

**Test first.** The estate can only hand this judgement one document shape, so it is driven on
fixtures. `step3_band.py --selfcheck` runs eight cases. Red first, with `judge_held` neutered to
`return None`: seven of the eight reported `wanted '...' in the reason, got None`. Green after:

```
PASS: selfcheck: 8 held-document judgements bite -- the tighten-only hold is accepted; nothing
proposed, a landed document, an error, a missing or wrong hold, a hold that should have tightened
and a hold with no basis are each caught
```

The wrapper now runs that selfcheck before the observation and fails the step if it does not bite.

**Proof.** `bash verify/e2e/verify-e2e-step3-price-crosses-band-pr-opens.sh` → exit 0, last lines:

```
    proposal: pull_request, held=tighten-only on line ico-feed
    driftwood declares posture.acme.io/tier: isolated on gitops/apps/namespace.yaml; the priced
    line selects restricted and the party folds to restricted, which does not tighten it, so
    nothing is written: ... held -- the proposer only tightens
    no branch created, gitops/apps/namespace.yaml unchanged on disk, the pod manifest untouched,
    nothing opened
PASS: a SYNTHETIC residual placed either side of driftwood's own signed appetite band of 40,000
GBP ... the proposer HOLDS (tighten-only, ADR-0022): no branch, no edit on disk, nothing opened --
the estate does not loosen a declaration to match a price
```

`verify/e2e/verify-e2e-step7-honesty.sh` (which grades the shape of steps 1-6, and requires a
step-3 PASS to say SYNTHETIC) went from FAIL to `PASS: steps 1-6 each report one honest verdict
(verdicts: SKIP PASS PASS SKIP SKIP SKIP PASS)`. The file name is unchanged: this is still
NORTH-STAR §4 step 3, and the price still crosses the band.

- `verify/priced-holes/verify-priced-holes.sh` →

  `deltas[]` until it is re-composed, and re-composing an adopter is an enactment push the owner

**Decision (delegated): two rows moved from `waits:` to `never:`.** `waits` means the estate's own

the script cannot pass on the scheduled runner as the runner is built. Ticket 63 pushed both
`verify-retirement.sh` and `verify-conditional.sh` past their offline refusals into live tails that
need a cluster, so on the runner they can never pass, and calling them `waits` would inflate the
published ceiling by two. This is arithmetic being corrected, not a check being relaxed: both
scripts still exit 3 and still count as skips.

**Decision (delegated): the kind rule, written into the manifest header.** When a script's
could-not-look **on the runner** is a missing substrate, its row is `never:`, and the pattern also
names the reasons the same tail prints where the substrate *is* there — so the row is true in both
places and a new reason still cannot hide inside an old declaration. When the runner's reason is
the estate's own state, the row is `waits:`. `verify-coexistence.sh` stays `waits` under this rule
because its branch fires before any substrate check.

## 8. `talk/verify-all.sh:145` — bare `xargs` used as a whitespace trimmer

Not a regression this build caused; a latent defect that produces three of the local artefacts and
silently truncates two exclusion reasons on CI. Fixed here because it is what makes the local
number readable.

**Cause.** `r="$(echo "${line#*|}" | xargs)"`. `xargs` is a word splitter, not a trimmer: it
quote-processes its input. Two reasons in `talk/verify-exclusions.txt` contain an apostrophe —
line 23 ("SPIRE is Istio's CA") and line 28 ("an adopter's reach to its secrets"). On those lines
**BSD xargs prints nothing at all** and warns `xargs: unterminated quote`, so the reason read back
empty, the gate printed `FAIL exclusions: '<path>' has no reason`, the exclusion was **dropped**,
and the script ran anyway. **GNU xargs** prints the reason truncated at the apostrophe, so CI has
been publishing two half-sentences.

**Fix.** A `trim()` helper using shell parameter expansion, used for both the path and the reason.
It touches neither quotes nor backslashes and needs no subprocess.

**Test first.** The selfcheck's excluded fixture now carries an apostrophe on purpose
(`a helper the others call, and SPIRE is Istio's CA`) and the assertion anchors the **whole**
reason. Red before the fix — four `selfcheck: missing: ^TRUTH ...` failures, each preceded by
`xargs: unterminated quote`, because the dropped exclusion shifted every count. Green after.

**Proof.** `bash talk/verify-all.sh --selfcheck` → exit 0, last line ends
`..., a stale or malformed manifest line is a fail, an exclusion reason containing an apostrophe
survives the trim whole, and a unit line this checkout does not carry is a note`.

  becomes a NOTE when the run is off the substrate the manifest was derived from. It was
  considered and not built: a `never`-classed script that passes off-runner cannot be counted as a
  pass without either exceeding the ceiling it was cut from or redefining `ceiling`, which is the
  one number NORTH-STAR publishes. That is `truth_manifest.summarise()`, the TRUTH-line
  arithmetic, `verify-truth-line.sh` and `build_deck.measured()` — its own ticket, not a line in a
  repair. The manifest header now says which substrate it is derived from, and this file names the
  rows that differ, so nobody re-diagnoses them meanwhile.
- **`tier_pr.py`** was not touched. The proposer is right.
- **Nothing was relaxed** to make a red go away. The reds in the two tables above are the estate's
  own state and stay red.
