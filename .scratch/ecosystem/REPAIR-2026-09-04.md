## 1. `verify/provenance/provenance.py` — KeyError on a field ticket 78 deleted

**Cause.** Ticket 78 removed `signed` from every proposal `wargamer.py` emits, on the ground that a
signature is a property of the *commit* — put there by `propose-tier.yml`'s gitsign step and read
back out of Rekor — and never a literal a proposal may claim about itself. `provenance.py` still
read `pr["signed"]` in two places: the PR link of the chain (:110) and the selfcheck assertion
(:219). Both died with `KeyError: 'signed'`, unmasked, because nothing on this machine's PATH was
missing to hide it behind a could-not-look.

**Fix.** Dropped `"signed": pr["signed"]` from the PR link dict, with the reason in a comment, and
replaced `assert pr["signed"] is True and "Rekor" in pr["identity"]` with the pair
`assert "signed" not in pr` / `assert "Rekor" in pr["identity"]` — the same assertion
`wargamer.py:483-484` now makes about its own output. The chain claims the identity **mechanism**
and never a signature the proposal does not have.

Ticket 76's `selfcheck_absent` leg needed no change: it reported the fault correctly.

## 8. `talk/verify-all.sh:145` — bare `xargs` used as a whitespace trimmer

Not a regression this build caused; a latent defect that produces three of the local artefacts and
silently truncates two exclusion reasons on CI. Fixed here because it is what makes the local
number readable.

**Cause.** `r="$(echo "${line#*|}" | xargs)"`. `xargs` is a word splitter, not a trimmer: it
quote-processes its input. Two reasons in `talk/verify-exclusions.txt` contain an apostrophe —
line 23 ("SPIRE is Istio's CA") and line 28 ("an adopter's reach to its secrets"). On those lines
**BSD xargs prints nothing at all** and warns `xargs: unterminated quote`, so the reason read back
empty, the gate printed `FAIL exclusions: '<path>' has no reason`, the exclusion was **dropped**,
and the script ran anyway. **GNU xargs** prints the reason truncated at the apostrophe, so CI has
been publishing two half-sentences.

**Fix.** A `trim()` helper using shell parameter expansion, used for both the path and the reason.
It touches neither quotes nor backslashes and needs no subprocess.

**Test first.** The selfcheck's excluded fixture now carries an apostrophe on purpose
(`a helper the others call, and SPIRE is Istio's CA`) and the assertion anchors the **whole**
reason. Red before the fix — four `selfcheck: missing: ^TRUTH ...` failures, each preceded by
`xargs: unterminated quote`, because the dropped exclusion shifted every count. Green after.

**Proof.** `bash talk/verify-all.sh --selfcheck` → exit 0, last line ends
`..., a stale or malformed manifest line is a fail, an exclusion reason containing an apostrophe
survives the trim whole, and a unit line this checkout does not carry is a note`.

## 9. `step3_band.py` — an "observation" that could not have observed anything

Found on the second pass, in the first pass's own new code, and fixed with fix 3.

**Cause.** The no-branch assertion ran `git -C work branch --format=%(refname:short)` in a
tempdir that was **not a git repository**, and the comment beside it argued the refusal *was* the
observation ("a proposer that had branched would have had to make one first"). It is not. `git
branch` outside a repository exits 128 and prints nothing whatever the proposer did, so the
guard `if branched.returncode == 0 and branched.stdout.strip()` was unreachable — and the run
then published `no branch created` on its PASS transcript as if something had been looked at.
That is the exact shape this project calls a green that could not look, written by the branch
that was cleaning up greens that could not look.

**Fix.** Each throwaway copy is `git init`-ed, its files committed, and the assertion is now
"no branch other than the copy's own `main`". A non-zero `git branch` is itself a failure —
`whether the run branched was not looked at` — instead of passing silently. The copies have no
remote and no credential, so the safety the old comment was reaching for is kept by a different
and stronger mechanism: the proposer's non-dry-run path dies on its own `git fetch origin main`.

**Proof.** In the PASS transcript, `both legs: no branch beyond the copy's own main, ...`, and
the two legs now cover the landed path as well as the held one, which is the path that would
branch if anything did.
