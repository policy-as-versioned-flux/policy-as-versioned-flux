## 3. "a dispatch there yields a consumer-accepted tag with no change to main" — CONFIRMED, with nuance

- `release/2.0.x` carries a working `cut-release.yml` (`git ls-tree origin/release/2.0.x
  .github/workflows/` -> `cut-release.yml`, `release.yml`).
- Its trigger is `on: workflow_dispatch:` with no ref guard, no `environment:`, and no
  `github.ref` condition anywhere (checked on that branch's copy, line 56-57).
- The branch copy is stale but the only delta vs main is the `backfill_evidence_only`
  input and its `if:` guards (`git diff origin/release/2.0.x origin/main --
  .github/workflows/cut-release.yml`). **The publisher-gate step is present on the branch
  copy.** So this is not a gate bypass — it is a review/authorization bypass.
- `release.yml` has no `merge-base` / `--is-ancestor` / `branch --contains` check; the tag
  is never required to be reachable from main.
- Nothing pushes to main: the workflow's last steps are `cut-release-create-tags.sh` and
  `cut-release-push.sh` (tags only) plus the backfill push to `github.ref_name`.

### CORRECTION A — "no check in the 84-script gate names it" is false

Two gate scripts name the branch class explicitly and grade its acceptance as PASS:

- `units/platform/verify-certificate-identity-regexp.sh:23`
  `"…/cut-release.yml@refs/heads/release/2.0.x"`
- `units/ico/verify-certificate-identity-regexp.sh:23` (same shape)

Run-21 capture (`git show origin/main:talk/captures/.estate-clone_platform_verify-certificate-identity-regexp.out`):
```
ok  matched: …/cut-release.yml@refs/heads/release/1.0.x
ok  matched: …/cut-release.yml@refs/heads/release/2.0.x
PASS: EXPECTED_IDENTITY_REGEXP accepts this repo's main and release/<major>.<minor>.x
```
The gate names the ref class and asserts it is *accepted*, by design. What no gate check
covers is **who may write to that ref, or dispatch from it**. The finding must say that.

### CORRECTION B — "consumer-accepted" must not read as auto-adoption

All three adopters set `"automerge": false` (`driftwood/renovate.json:8`,
`ludlow/renovate.json:6`, `tuppence/renovate.json:6`). A tag cut this way passes the
adopters' *signature* check but still needs a human-merged pin bump to reach a cage.

## 4. The genuinely new exposure over SS-04 (stronger than the finding argues)

The finding frames the marginal value as "even if main were protected". There is a second,
present-tense difference the finding does not claim: **the truth surface cannot see it.**

- `clone-estate.sh:38` — "this clones the default branch".
- Run 21 records `platform=46cd775`; `git rev-parse --short origin/main` = `46cd775`,
  `origin/release/2.0.x` = `860e744`.

So all 84 gate scripts run against main's tree. A release cut from `release/2.0.x` changes
no file the gate reads, and TRUTH would not move.
