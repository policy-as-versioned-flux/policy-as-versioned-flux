## Where the claim overstates (three corrections)

**(a) The line's money is not the platform's.** `amount` = £1,897,646.11 is
`fair.summarize(fair.simulate(lef, payload["lm"]))` (`composition.py:1745-1752`) over driftwood's
own `lm` triple `[192000, 384000, 800000]` (`driftwood/twin/forward-intel/v1/feed.json`) with a
frequency borrowed and **named** from feeds' `threat-register` (`lef_from` on the entry).
`platform/fair/fair.py` imports no cage table (`grep TIERS` → no hits). Only the `residuals` map,
and therefore the rung, is the platform's. "The priced entry is computed from the platform's
numbers" is wrong about the headline figure.

**(b) £171,600 is a different quantity at a different scale.** `verify/pound-seam/pound_seam.py:482-491`
computes it as `impact*(1-reduce)+cost` at `impact = lm[1] = 384,000` — net cost of risk on **one
shock**, cage operating cost included. Re-derived: table 269,300 / 117,200 / 36,720 / 22,680 vs
curve 372,800 / 288,800 / 176,400 / 133,400; max spread 171,600 (at `restricted`), both pick
`isolated` as cheapest. The entry's residuals are annualised and an order of magnitude larger.
Quoting 171,600 as the gap "per rung" in the price line mis-scales it.

**(c) It is a recorded decision, not an accident — but the record it contradicts is ADR-0021, not
REGRILL 33.** Ticket 08 answer 4 (`.scratch/ecosystem/issues/08-the-pound-seam.md:24`): "The curve
never picks... Version 1 is the existing rule (first tier whose caged residual is under tolerance)."
driftwood's own signed package says the same in its own words:
`selection-policy/selection_policy.py:2` ("The curve never picks; this does") and `:55-56`
("the caged residual under each tier, **from the estate's own pricing**"). REGRILL 33's words are
"One currency, many perspectives: one unit; each party prices under its declared perspective; no
perspective privileged" — and the entry does carry `perspective: driftwood`, in driftwood's
reporting currency, judged against driftwood's own signed £40,000 appetite, picked by driftwood's
own versioned package. The record that the code actually contradicts is
`docs/adr/0021-...md:18-20`: "a versioned, signed selection policy package... **turns the curve
into one tier**". The shipped code turns the *platform's residual ladder* into a tier and only
hashes the curve (`composition.py:1784`).

## Where the claim is too weak (the part worth keeping)

The finding calls the disclosure "exemplary" and stops. The substitution changes what the entry
**asserts**, not only which table produced a number.

Recorded on the entry: `policy_basis: "loosest tier whose caged residual (37952.92 GBP) is within
the tolerance (40000.00 GBP)"`. Run the identical operation with driftwood's own published mode
reductions instead:

| rung | platform table | driftwood's own reductions |
|---|---|---|
| baseline | 1,328,352.28 | 1,802,763.81 |
| restricted | 569,293.83 | 1,328,352.28 |
| quarantine | 151,811.69 | 664,176.14 |
| isolated | **37,952.92** (inside the £40,000 band) | **189,764.61** (4.7× the band) |

Under driftwood's own numbers **no rung is under tolerance**. The rung would still come out
`isolated`, but by failing closed (`selection_policy.py:16,33` `FAIL_CLOSED`), not by fitting. So
the sentence driftwood's signed evidence carries — that the cage brings it inside its own appetite
band — is true only of a table driftwood did not author and explicitly disagrees with.

The pound_seam guard cannot see this by construction: `pound_seam.py:443-445` states its ceiling as
"the per-rung reduction is not [checkable], because the curve publishes one figure per rung... and
two unknowns behind it". True of the **feed payload**; not true of driftwood's repo, where
`responses/*.yaml` publishes `mitigates.reduction.mode` and `cost` separately and
`twin/emit-forward-intel.py:202-204` builds the curve from exactly those two fields.
