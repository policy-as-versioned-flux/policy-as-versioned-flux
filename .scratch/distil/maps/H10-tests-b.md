## Summary
- Of 41.5k lines, about 3.9k (components 1-3, 5, 7) exercise code that is on the loop at all: loss curve, propagation, trade-off, scoring, money inputs, backtests, signal pool. The rest tests twin plumbing, the model-qualification programme, PDF-tool observation, the build's own truth line, and the build's own agent cage.
- Nothing in this area asserts the Tolerance, Compare, Ratchet or Enact steps. A case-insensitive grep for appetite, tolerance, ratchet over the 95 test files finds only: a byte-identity "tolerance" (test_reproduce.py:70), an evidence-grade `appetite.pricing_threshold` literal in three files, and a scheduling tolerance (test_verdict.py:46). The one real "price crosses the adopter's appetite band, PR opens" step is `verify/e2e/step3_band.py` (662 lines; outside this area; no test here).
- "Appetite" in `twin/` is `appetite.pricing_threshold`, an evidence-grade number 2 or 3 (twin/evidence.py:51-58), not money. Money tolerance is `appetite.tolerance` in party.yaml, read by verify/e2e/step3_band.py (docstring) and cross-checked against platform/graded/cage.py. Neither is tested from here.
- About 23.9k lines (57%) date from 2026-10-30/31, the Codex calibration programme: 9.0k in tests, 14.9k in bench (Linux containment 5.6k, Xpdf origin 7.5k, Qwen smoke 1.0k, controls 0.8k). Of bench/pinned-candidate only test_linux_network.py is run by a workflow.
- Authorship caveat: all commits under tests/ and bench/ carry the owner's git identity (372) or the pavc-other-hand bot (13), so origin is inferred from epoch and commit style, not from a trailer.
- `hub/t` is three stray Kyverno-CLI fixture files from 2026-08-20; `kyverno-test.yaml` names `mp.yaml`, absent from the directory; nothing references them.

## What the loop would lose if this area vanished

- Quantify: the property tests that pin the loss curve (TVaR on a spliced lognormal+GPD tail), shock propagation and the cost-of-response curve (components 1, 2), about 1.4k lines. The quantification code (twin/severity.py, propagate.py, tradeoff.py) would still run, but silent numeric regressions would go undetected.
- Evidence the quantifier is calibrated: scoring tests and backtest keys (components 3, 5), about 1k lines. These are the only tests in the area that could say the money figures are wrong.
- Cage correctness: the refusal-by-another-name, unreviewed-major and untagged-pin graders (component 20) guard the policy bodies that are the cage; the signature graders (19) guard their authenticity. Together 2.3k lines. Losing them removes tests of the cage rungs, not of any ratchet that moves between rungs.
- Tolerance, Compare, Ratchet, Enact: nothing is lost, because nothing here tests them. Those steps are tested, if at all, in verify/e2e (step3_band.py, step4), in the other test half, and in platform.
- Everything else (about 37k lines, 89%) can vanish with no change to what the loop can do: model qualification, PDF-tool observation, Linux containment source, TRUTH-line machinery, the twin-agent cage, sensor admission, the Flux verdict, the loophole harness.

## The simplest thing that would do this area's loop job

One file, `tests/test_loop.py`, about 150 lines, plus the existing severity and propagation property tests (about 1.1k lines, kept). It builds a three-component synthetic organisation with a signed `party.yaml` carrying `appetite.tolerance` in pounds and asserts the six steps in one pytest:

1. The loss curve from twin/severity.py pushed through twin/propagate.py gives one exposure figure in pounds (assert equals a hand-computed figure).
2. `exposure > tolerance` is True.
3. The ladder in twin/enforcement.py plus the cage selector (platform/graded/cage.py) returns the next tier; assert exactly one notch tighter and that residual exposure falls.
4. The proposer (the code driven by verify/e2e/step3_band.py) writes the tier-declaration edit; assert the diff touches only `posture.acme.io/tier`.
5. Feed a new price signal (twin/feed_signal.py); assert exposure is recomputed and the loop either stops or ratchets again.
6. Assert termination when exposure is at or under tolerance, and that a missing appetite refuses rather than defaulting.

verify/e2e/step3_band.py (662 lines) already does steps 2 to 4 offline; the missing piece is one asserting test that closes the loop through steps 5 and 6. The remaining roughly 40k lines in this area would be archived outside the tested tree.

## Surprises

- The largest single test file (test_sensor_admission.py, 1,640 lines) is one risk class's privacy gate (bus factor) and names no person. It is more than twice the size of the severity, scoring and trade-off tests combined (759 lines).
- 23.9k lines (57% of the area) date from 2026-10-30/31, two days. They qualify a pinned 4B-parameter model (Qwen3-4B-Instruct-2507), its Linux sandbox and an Xpdf build, yet the bench README says the probe does not "connect a candidate to operational judgement" and the Linux docs say the harness "has not been installed or executed".
- 32 of the 95 test files state TEST_ONLY in their opening docstring (qualification, qualified_*, task_*, source_*, xpdf_*): they prove a mechanism refuses to claim something, not that the loop does something.
- The only "cage" in components 22 and 24 confines the build's own agent and a model process, not the organisation's process cage in the mission. The tests of real cage rungs are component 20 (1.6k lines).
- "Appetite" means two things: an evidence-grade threshold 2 or 3 in twin code (twin/evidence.py:58) and the money `appetite.tolerance` in party.yaml. twin/enforcement.py:233 says the bottom rung is reached "when the rung below it still leaves a residual over the appetite band", the only place I found the ratchet-until-within-tolerance rule stated in code this area touches.
- Not all bench lines are code: 1,405 are copied GPL notices, 1,097 a JSON schema, and the loophole rounds are three same-sized result sets (candidates.json 86, summary.json 126, calls.jsonl 8 per round; not diffed).
- "Calibration" means two things: twin/calibration.md (2026-08-06) is the PERT-triple 90%-interval procedure (a quantify aid), while the "calibration programme" from 2026-10-30 is model qualification. Only the former serves the loop.
- Graders under verify/ are loaded by the tests through `importlib` file paths, not package imports, so renaming a verify script breaks these tests; I did not run the suite to see how loudly.
- `hub/t` is dead scratch.
