## What the loop would lose if this area vanished

- Ratchet and enact would go. `select_party_tier` plus `tier_pr.py` are the only code that turns a priced tier into a pull request, and `tier_binding.py` is the only gate that stops a hand edit loosening the declared tier. In practice they have never landed a move, because every adopter is already at `isolated`.
- Quantify would lose the cve/eol feed-to-scenario step (`to_fair_scenario.py`, which composition calls) and the served-image CVE set (`inventory.py`).
- Evidence would lose `result2oscal.py` (daily control-satisfaction observations) and the gitsign verifier (proof the policy source is the pinned publisher's).
- Compare and tolerance would lose almost nothing: they live in `compose/` and the adopters' `selection_policy.py`. This area holds only the platform's own 10,000 GBP band and a demo of the compare.
- Everything else (identity substrate, federation, access, posture SVIDs, eud, wardley, calibration, reflexive, release twins, lint, lib) could vanish with no change to any loop step. They serve workload identity, human/device access, a talk, or process assurance.

## The simplest thing that would do this area's loop job

One module `ratchet.py` (about 250 lines) in the tools tag, three functions.
1. `fold(prices, current, floor) -> tier or None`: strictest `proposed_tier`, clamp up to floor, return only if tighter than `current`. The live logic of `select_party_tier` is about 40 lines once the prose is removed.
2. `land(adopter_dir, tier, body)`: set `posture.acme.io/tier` on the one governed Namespace, push one fixed branch name, create or update one PR with before/after residual in the body. This is the working core of `tier_pr._land` plus `_move_evidence`.
3. `check(evidence, namespace) -> exit code`: refuse a declared tier looser than `fold(...)` (`tier_binding.bind`).

Keep `feeds/to_fair_scenario.py` (about 450 lines) for quantify, `inventory.py` (about 290), `result2oscal.py` (about 226) and `party.yaml` for tolerance. Replace `rejection_ledger.py` and `proposer_bounds.py` with the rule "one open PR per fixed branch name", which `tier_pr` already enforces, until a real rejection exists to learn from. Total roughly 1.3k lines instead of 16.9k. The largest deletions would be identity (SPIRE, federation), access, posture/spire, eud, wardley, the release twins and the in-file selfchecks.
