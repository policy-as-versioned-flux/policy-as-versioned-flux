## What the loop would lose if this area vanished
- The loop itself would lose nothing: no file here quantifies, compares, ratchets or enacts. Quantify lives in platform/fair; ratchet and enact live in the platform/adopters (not read here).
- It would lose its only independent "did anything run" instrument: verify-all, the TRUTH line, the manifest class split and the capture record. That is evidence, and it is why the harness is "support": without it nobody can tell a ratchet occurred, but with it only 42 of 117 passes observe another party.
- The delivery code would take with it the route by which clock observations reach protected main.
- The talk specs would take the best prose statement of the loop (below), which exists nowhere shorter.

## The simplest thing that would do this area's loop job
One file, `loop-ledger.csv`, one row per cycle: `date, exposure_gbp, tolerance_gbp, within(bool), tier_before, tier_after, pr_url`. One script of about 60 lines (`gate.sh`) that runs only the verifies for the six loop steps (quantify, tolerance, compare, ratchet, enact, react), prints one line `LOOP date exposure=£X tolerance=£Y tier=N within=yes|no`, and appends it to the ledger. About 80 lines in total. Keep the three-state grade (pass / fail / could-not-look) from verify-all.sh (about 40 lines of it) because that single idea is what stops a green lying. Drop manifest classes, ceiling arithmetic, fall_check, delivery controller and .pyz (about 6,000 lines), and replace the deck with a README that renders the ledger.

## The one-minute story, in the talk's own words
Assembled in order, quotations verbatim from `.scratch/talk-spec/pitch-v4/script.md` (S1 to S12), `talk/narration.json` and `.scratch/talk-spec/the-whole-model.md`:

1. Quantify: "What does a breach actually cost you? Not a red, amber, green light — a number, in pounds." (S1, script.md:7)
2. The thesis: "governance as a priced, versioned, continuously re-tuned judgement. Not a checkbox. A number that moves, because the world moves." (S2)
3. Tolerance and compare: "Identical risk bought — twenty one thousand, one hundred and seven pounds, on every single cluster. ... For the retailer, that's under budget: it audits. For the fintech and the hospital, it blows the budget: it blocks. Same rule. Opposite verdict. Because the pounds say so." (S5)
4. Ratchet: "it's never just yes or no. Fall behind on patching, your workload doesn't get killed — it gets caged. Throttled, sandboxed, watched, more expensive to keep running." (S6)
5. The ratchet moving on its own: "The adopter published an appetite band. A residual crosses it, and the tier the workload runs under moves up a rung ... Then the machine stops. It opens a pull request ... and waits for a human." (narration.json, step 3)
6. React: "Real threat feeds, new vulnerabilities, regulator fines — all pouring in. An agent stress-tests every control and asks: is this still proportionate, or did the world just move? When it drifts, the agent does exactly one thing: it opens a pull request. It proposes. It never disposes." (S10)
7. Enact: Flux "is the plane distributing every signed policy, to every cluster, provably." (S14)
8. Honesty: "A check that passes because it could not look is worse than one that fails." (narration.json, deck slide 15)

Tightest form in the model's own sentence: "Governance is a proportionate, informed, continuously re-tuned response to quantified risk" (the-whole-model.md:12-14). Note it carries "appetite" (tolerance), a "cage tier" ratchet, "feeds" and a "proposer" (react), and "Flux" (enact): the same six steps. It does not say "stop when exposure is within tolerance"; the talk never states the stopping condition.
