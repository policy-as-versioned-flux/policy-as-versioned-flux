## What the loop would lose if this area vanished
- Nothing runs the loop from here; these are all test inputs. Loss would be assurance, not capability.
- The one piece that matters: `publisher_price_fixture.py` + `test_publisher_price_vertical.py` is the only offline test in this area that drives the real `compose` against an adopter tolerance and checks that a priced hole or worse distribution changes the outcome (test names at tests/test_publisher_price_vertical.py:18,201,271). Without it the Q->T->C path through composition would lose one end-to-end offline check. It still fakes the signature boundary, so it proves nothing about authenticity (publisher_price_fixture.py:70-85 prints the synthetic-boundary banner).
- recovery-expense-v1.0.2.json is the only fixture here that is a genuine quantified-risk input (LEF and loss magnitude in GBP), and what it tests is that a publication becomes a *signal*, not a price. The loop would lose that regression test and no numbers.
- Everything under TEST_ONLY-* (721 lines) and tu-observation-cloud (851) tests tooling for retained source metadata and observation delivery. The loop would lose nothing it can currently use. I found nothing in this area that feeds a quantification, a tolerance comparison, a ratchet notch, or enactment.

## The simplest thing that would do this area's loop job
One pytest file, ~80 lines, `tests/test_loop_closes.py`, no fixtures directory. It would:
1. Build one tolerance of 15 and one scenario with `lef=[1,1,1]`, `lm=[5,5,5]` in memory (the numbers already in test_publisher_price_vertical.py:42-45).
2. Call `compose()` once with the cage as-is and assert exposure > tolerance. Call it with one notch tighter (`deny` scenario) and assert exposure is below. Call it again after one signal changes `lm` and assert exposure rises above tolerance again.
3. Use `conftest.py` reduced to the repo fixtures (~40 lines); drop the signing-key guard, local-clock copy and `-n auto` unless suite time demands it.
Rough total: ~120 lines of test infrastructure in place of 2,295, with the PDF/xpdf/source-metadata/Tuppence fixtures (1,572 lines) deleted along with their consumers (test and prod, outside this area).

## Surprises
- The assigned range holds almost no tests: the A-to-P split by file name captured 2 entries, because the suite is `test_*.py`. Work done by the other reader on 'q'-'z' will carry virtually all 59,585 test lines.
- 68% of this area's lines (1,572 of 2,295) are fixtures for the Oct 17 - Nov 2 observation-delivery, source-metadata and xpdf-native-observation work. Their own READMEs and docstrings disclaim evidential value ("not converter/PDF/native execution evidence"; "No successful delivery or world grade follows from these tests"; "Noncase TEST_ONLY").
- The xpdf build fixture's commit is titled "unappointed fixed Linux build-only capability" (4676fbac): code built and tested but, by its own docstring (build_linux_pair.py:2; twin/pdf_remap_resources.py:3-4), with actual appointment and wiring "held". `docs/pdf-output-origin.md:6` says the profile "is deliberately absent from the migration executor's supported profile table", so the PDF machinery is also unreachable from the running system. Nothing I read ties it to the loop.
- recovery-expense-v1.0.2.json's own `lef_basis.kind` is `normative-planning-unvalidated`: its annual frequency [0.25, 1, 3] is a "chosen uncertainty bound, not evidence-derived rate". This is the only quantified-risk-in-money fixture here, and it declares itself unvalidated.
- `publisher_price_fixture.py` needs sibling clones at `hub/.estate-clone/{platform,nist,feeds}` or env `PAVC_PRICE_TEST_SOURCES` (lines 22-31); it is not present in the fresh clone. CI satisfies it via `bash clone-estate.sh` before `python -m pytest -q` (.github/workflows/twin.yml, test job). The test cannot be run from this repo alone, and I did not run it (read-only).
- `conftest.py` imports `twin.fixtures` (5,951 lines), so every test in the suite, including pure-signal tests, pays for the toy-model builder only when requesting those fixtures (session-scoped, lazy). The autouse signing-key guard, however, runs on all 211 files.
- `local_clock_hub` copies four whole trees (`twin`, `talk`, `verify`, `.claude`) per test and is used only by two test files (grep: test_local_clock.py, test_derived_forecast.py). It exists because concurrent xdist workers wrote bytecode into the checkout (commit 97a35410), a problem the clock itself created by auditing its own executable inputs.
- Authorship cannot discriminate origin: `git log --format=%an` for every path in this area returns only the owner's name; hub-wide it is 1052 owner, 218 `pavc-other-hand[bot]`, 182 `truth surface`. Origin labels here are inferred from commit dates and the project's epoch notes, not from attribution.
