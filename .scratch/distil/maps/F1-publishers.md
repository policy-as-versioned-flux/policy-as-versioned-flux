# F1 - The publishers: nist, ico, feeds, insurer

Read-only review, 2026-11-14, of FRESH clones (hub/platform/adopters read only to find consumers). Paths below are relative to FRESH unless stated. `repo/path:line` is the citation form.

## Summary

- Four repos, 233 files, 108,732 lines (wc -l). 85,412 of them are `feeds`, and 73,285 of those are one feed (cve): a 58,882-line raw capture and a 13,903-line payload. Strip data and the code is roughly 16,000 lines.
- Measured by bytes, data is 94% of nist (the 4.9 MB OSCAL catalogue), 92% of feeds, 37% of ico and 26% of insurer. The money-bearing content (fine formulas, threat triples, KEV/EPSS rows, four EOL rows, rate table) is a few hundred numbers.
- What moves an adopter's pound today: ico penalty-schema v3 (the dominant feed-priced line for all 3), threat-register v4 (all 3), cve v3 (only tuppence, GBP 437,107, 2 Log4j CVEs), eol v2 (ludlow only, GBP 787,228), fx (ludlow only, indirectly: USD turnover to GBP), insurer quote-driftwood (driftwood only, a premium booked as cost, outside the aggregate-vs-tolerance sum). The nist catalogue moves no pound; it supplies 18 control ids used.
- Published but unconsumed by money: market-moves and news (never tagged, no adopter pin), recovery-expense (pinned by all 3 but excluded from prices), nist publisher-reliability and the monetary SDK (zero cohorts), insurer quote-tuppence and quote-ludlow (no adopter inherits them), ico v4 (only priced as a "supersede" surcharge).
- feeds has six fetch adapters (cve, eol, fx, market-moves, news, threat-register; recovery-expense has no clock). Only cve and fx read a primary source; the other four re-read a committed fixture (`feeds/fetch/lib.py:43`), so "react" is a heartbeat there. Where the clock did find change (fetch/cve-3.1.0 of 2026-10-05, fetch/fx-3.0.0 of 2026-10-04) the proposal sits unmerged.
- October (largely Codex) added ~9,640 lines to nist (76% of that repo) and ~855 + 952 lines of duplicated adapter ABI to feeds and ico. None of it moves a pound: every report set and cohort is declared empty.
- No publisher holds the organisation's tolerance. It lives in each adopter's `party.yaml` `appetite.tolerance` (driftwood GBP 40,000, tuppence 15,000, ludlow 5,000). The insurer reads it as its attachment point.

## Per-publisher facts

### feeds (policy-as-versioned-feeds, 95 files, 85,412 lines; first commit 2026-08-28; 12 non-merge Oct-2026 commits of 29)

Data against code: code/CI/tests/verify 4,978 lines (255,885 bytes, 7%); data, schemas and config 79,805 lines (3.27 MB, 92%); docs 629. Every feed is an envelope (`kind, name, version, published_by, published_at, payload_schema, payload`), signed only by the gitsign tag `<feed>/vX.Y.Z` (`feeds/README.md:15-39`). Tags that exist: threat-register v1.0.0, v2.0.0 (2026-09-01), v3.0.0 (09-10), v4.0.0 (10-03), v4.1.0 (10-23); cve v3.0.0 (10-03); fx v1.1.0 (10-03), v2.0.0 (10-04); eol v2.0.0 (10-17); recovery-expense v1.0.0, v1.0.1, v1.0.2 (all 10-23). market-moves and news have no tag at all.

**threat-register.** Publishes per institution a headline threat with `lef` and `lm_gbp` PERT triples, each with a `*_basis` carrying kind, as_of and a could_not_look, plus a `threats` map. Sample (v4, driftwood): `"threat": "cart/checkout PII exfiltration", "lef": [2,4,9], "lm_gbp": [1000,4000,9000], "lef_basis.kind": "editorial"`, and row `scheduled-agent-misuses-write-credential` with `lef [8.4186e-05, 8.4186e-05, 0.00029465]` from N x C / M (`feeds/threat-register/v4/feed.json`). Changes by human-reviewed PR after a ticket (v2 raised tuppence lef; v3 moved magnitudes out of platform; v4 added the agent row); the clock reads `fetch/source/threat-register.json`, a committed fixture, and recorded 'none' on all 41 runs since 4.0.0 (all 69 observations counted: 3 distinct payload hashes). Consumer: all three adopters pin v4 (`driftwood/party.yaml:72`); platform composition prices the headline entry (`platform/compose/composition.py:452`), and the platform twin-agent cage reads the agent row (GBP 0.00 / 18.70 / 2.98). Loop step: Q. Today's pound: driftwood 19,558.55; tuppence 326,139.13; ludlow 318,229.78 (HANDBOOK section 4 of each adopter).

**cve.** Publishes `severity_lm_gbp` (four editorial bands: critical [50000,150000,400000] ... low [100,1000,5000]) and `cves`, 1,733 CISA KEV entries each with component, cvss, severity, epss, published, source (`feeds/cve/v3/feed.json`). ## What the loop would lose if this area vanished

- Quantify (Q): everything. ico penalty-schema and threat-register are the only sources of money in the three adopters' feed-priced lines; without them the aggregate is empty. cve, eol and fx would remove tuppence's GBP 437k, ludlow's GBP 787k and ludlow's currency conversion; the loop would still run on the rest.
- Tolerance (T): nothing. No publisher holds it; the insurer only echoes the adopter's `appetite.tolerance`.
- Compare (C): nothing directly, but cve returning no intersection is what turns two of three compares into NO VERDICT today.
- Ratchet and enact (R, E): nothing. Cage selection and enactment are platform and adopter code. nist's control ids are the label on a cage (ac-6 binding) and the holes vocabulary, which the loop could carry as a list of 18 strings.
- React (X): the cve and fx clocks are the only feed-side reaction to the outside world, and neither has landed a change since 2026-10-05; the reaction stops at a human merge. market-moves and news react to nothing.
- Evidence: signed tags, the observation lane, and the hash-per-day heartbeat would go. The scorer in nist has produced no measurement to lose.

## The simplest thing that would do this area's loop job

One publisher repo (or one directory in the hub) with four small data files and one fetch script, signed by one git tag; roughly 450 lines of data and 120 of code instead of 108,732 lines in four repos.

- `fines.json` (about 150 lines): for uk-gdpr, pci-dss, hipaa, fca, per violation type `{formula: {rate, cap}, final_fine_gbp, frequency: [lo,mode,hi], basis}`. This is today's `penalty-schema/v4` minus the 3 earlier majors, the legacy schema and the adapter.
- `threats.json` (about 60 lines): per institution `{lef: [..], lm: [..], basis}` plus the agent-misuse row. This is today's threat-register v4 payload.
- `kev.json` produced by `fetch_kev.py` (about 60 lines): CISA KEV joined to EPSS, written only as `{cve_id, epss, cvss}` for CVEs found in an adopter's inventory. This replaces 73,285 lines.
- `controls.txt` (18 lines): the control ids actually used; keep the OSCAL catalogue as a pinned upstream URL instead of a 4.9 MB copy.
- `price(entry, turnover_gbp)` in one function (about 60 lines, the core of `ico/schema/to_fair_scenario.py:206-265` and `feeds/threat-register/to_fair_scenario.py:88-179`), and a one-line premium formula inside the adopter's own file (`layer x 0.035 x 1.25`).
- Drop: fx (state turnover in GBP), eol (a row in threats.json when it matters), market-moves, news, recovery-expense until it holds observed data, the publisher-reliability and monetary SDK until it has one cohort, the three copies of the adapter ABI, the legacy ed25519 schema, and the unconsumed insurer quotes.
- Keep one daily job that fetches KEV/EPSS, recomputes the adopter's figure, opens a PR if it moved, and appends one line to a log; the existing `fetch/lib.py` plus `bump.py` (542 lines) already does most of this and could be cut by half.
