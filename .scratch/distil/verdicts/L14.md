### What would be lost: lessons, mostly in the engine grader and the fix commits

`git log --format='%ad %s' --date=short -- computed-semver/` gives 36 commits. These encode lessons the minimal loop's cage tests need:

1. **An Excluded row counts as a pass in Kyverno 1.18.2.** If a Pod sits in a Namespace the CLI does not know, against a `namespaceSelector`, `kyverno test` counts it as PASS whatever the row asserts. The grader refuses any pass or fail row that reads `Excluded` (`engine_compatibility.py:240-258`). It also requires exactly one summary, at least one passed assertion, no failed assertion, and one printed row per counted assertion (`:261-286`). The target cage reads its rung from the governed Namespace, so this trap applies directly.
2. **A fixture must name the body.** Every row must name a policy in the served file, and every policy must be named by a row. A body the CLI can evaluate needs at least one pass or fail row (`:292-308`).
3. **Grade a generator by what it generates.** Kyverno 1.18.2's `kyverno test` reads an unmatched generate trigger as Pass/Excluded even when a row expects output; 1.19 returns no result (upstream PR #16505). So the grader runs `kyverno apply -o` and compares the generated documents (`:320-369`). cage-netpol generates the NetworkPolicy that the target's network probes test.
4. **A vacuous pass when no rule loads** (commit d0fd9ff). A wrong path made kyverno load 0 rules, print no error and exit 0. The fix asserts that at least one rule was applied.
5. **No kyverno is could-not-look, not green** (commit 4f73609). Seven scripts exited 0 without the CLI; now they exit 3. The `lib.sh` convention outlives the directory, but it was learned here. It matches the target's "no measurement, no move".
6. **Self-scope gives a vacuous match** (commit 860e744). A body that self-scopes on a version label skips a pod pinned to another version. Comparing old and new bodies then reads a skip as "admitted". The fix neutralises only the named `only-this-policy-version` condition, on a copy of each side.
7. **A dial or declaration comparison cannot see a loosening** (commit bb204e8). Comparing only the dial table missed two real changes in 4.0.0: the tier source moved from pod to Namespace, and 3.0.0 wrote `readOnlyRootFilesystem: false` over a workload that declared `true`. The fix evaluates each side's own tier expression and compares the effective security fields. This applies directly to the proposed "each rung closes at least what it closed last release" test. If that test compares `rungs.yaml` lists, it repeats the defect. It must run the old and new bodies over the same pods.
8. **The branch goes with the tag** (commit b83eba1, the fix is in `.github/scripts/cut-release-push.sh`). An evidence commit reachable only from a tag stranded a later release. This bears on the target's signed release workflow if it commits anything before tagging.
9. **The engine pin.** Every live line lists `kyverno: ["1.18.2"]`, and 7.0.0 also lists 1.19.1 (`platform/distribution/versions.yaml:146-152`). The checksummed versions sit in `platform/engine/kyverno/engine-table.yaml`, outside this directory. The grader is what proves a body compiles on the version the cluster runs.

### What would not be lost

- A release number that tells major from minor from patch. It has never been exercised: see the evidence records above.
- A guard on the ratchet. The gate's own limits say it has none (`coverage.py:508-527`).
- Anything that moves money, rung or verdict.

## What the minimal loop must absorb

- The cage 8 consumer test (and any rung test) must refuse Excluded pass or fail rows; require one summary, at least one pass, no fail, and rows equal to assertions; require every policy to be named; and grade cage-netpol by `kyverno apply -o`, comparing the generated documents. About 120 lines, lifted from `engine_compatibility.py:229-369`.
- The release rung test must be behavioural: old and new bodies over the same fixture pods, with the self-scope condition neutralised if the bodies still self-scope. It must not compare `rungs.yaml` lists (bb204e8).
- Assert that at least one rule loaded (d0fd9ff). Kyverno absent means exit 3, could-not-look (4f73609).
- Run the consumer test on the pinned engine version (1.18.2, checksummed in `engine-table.yaml`).
- The signed release workflow must drop `release.yml:103-129` (the evidence check). It must not run a `ci-check.py` that loads the grader (`release.yml:83-87`).
- The atomic push of branch with tag (b83eba1), if the workflow commits anything before tagging.

## Recommendation: park

Park the directory at cut-over, in the same change as the composer. Keep it in history. Do not cut it outright: the grader's anti-vacuous rules are hard-won, and the target should lift them, not lose them. A "shrink" would mean keeping `engine_compatibility.py` where it is. It is cleaner to move the roughly 120 lines named above into the cage 8 consumer test, and park the remaining 14,400. That makes this park plus a small graft, not a keep.
