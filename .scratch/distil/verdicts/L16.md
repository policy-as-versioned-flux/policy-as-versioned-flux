# L16 — Platform: CI and front page

Verifier's working, 2026-11-14. Read-only. Paths are `repo/path:line` under `scratchpad/fresh/`.

Terms. **gitsign**: a tool that signs a git commit or tag with a short-lived certificate tied to an identity (here, the GitHub Actions workflow that ran), instead of a long-lived key. **Rekor**: the public log that records each such signature; an "offline" check uses a copy of the log entry embedded in the tag. **Identity pattern**: the regular expression a verifier requires the certificate's identity to match. **Shift-left**: platform's pre-merge check that runs `kyverno apply` of a policy version against a workload. **Engine cells**: one Kyverno binary per row of platform's engine table, each grading every policy line.

6. **recovery-expense.yml** tests `recovery-expense/` and `compose/test_shadow_recovery.py`, a shadow family "with no institutional financial effect" (`recovery-expense.yml:30`; map P2 #21).

8. **README.md, CONTEXT.md, LICENSE, .gitignore** are read by no code.

Result: at a fixed, already-signed tag, the loop (today's and the target's) runs with every file in L16 absent. **This attempt succeeds for day-to-day running.**

## Attempt 2 — the loop breaks or loses something without L16

The target platform is new code (loop.py, probe.py, inventory.py, cage version 8). It must reach driftwood as a new signed tag. Only one thing in the estate can make a platform tag driftwood will accept.

**The identity names this file.** driftwood verifies platform tags against a literal pattern that ends in this workflow's path:

```
^https://github\.com/policy-as-versioned-platform/platform/\.github/workflows/cut-release\.yml@refs/heads/(main|release/[0-9]+\.[0-9]+\.x)$
```

It is typed independently in four driftwood places:
- `driftwood/.github/scripts/platform-tools.py:20-22` (the loop's own tool check, run every cycle at `propose-tier.yml:128-131`);
- `driftwood/.github/scripts/adopter-gate.py:94-97` (comment at `:86-92`: "A platform workflow rename changes the identity string a real Fulcio cert would carry … verification breaks, on purpose (cs-28)");
- `driftwood/gitops/platform/platform-pin.yaml:27` (in-cluster verifying controller annotation);
- `driftwood/drift/five-facts.py:1949` (test).

`git for-each-ref --format='%(taggername)' refs/tags | sort | uniq -c` gives 38 tags by `policy-as-versioned release bot` (set by `cut-release-create-tags.sh:24-25`) and 2 by `cloud-release` (the two `cloud/v*` tags, `cloud-release.yml:50`). So every `v*` and `policy/v*` tag was cut by `cut-release.yml`. Recorded observation that the chain works: driftwood commit `18f1c3c` (2026-11-13, author "wargamer proposer", branch `origin/wargamer/retune-driftwood-served-images`) is an inventory proposal. In `propose-tier.yml` the only job is `propose-tier` (`:87`); the tool check is at `:128-131` and the inventory step at `:285-306`, later in the same job, so a failed check would have stopped the job before that commit. I infer from this that the offline verify of `v6.3.0` passed on 2026-11-13; I did not see the run log.

So: **without a workflow at exactly `platform/.github/workflows/cut-release.yml`, run from `main` or `release/X.Y.x`, no new platform release can be verified by driftwood without editing four driftwood files.** The loop would be frozen on the old chain at `v6.3.0`. **What blocks cutting the 8.0.x tag with today's file.** `cut-release.yml` as written cannot outlive the parking of computed semver:
- the gate step runs `cut-release-gate.py` for every dispatch (`cut-release.yml:142-147`), and that script imports `computed-semver/{comparison_window,corpus_generator,gate,release_integrity}` at load (`cut-release-gate.py:74-81`), even for a bare `v*` tag it then skips;
- the engine-cells step runs `computed-semver/engine_compatibility.py` and `engine/install-kyverno-engines.sh` for every non-backfill dispatch (`cut-release.yml:149-169`);
- `release.yml:83-87` gates every tag on `shift-left/verify-shift-left.sh`, which is not in the target.
Whether the engine-cells step would pass for a cage-8 commit could not be determined without running it. The safe order is therefore: shrink `cut-release.yml` in place on `main` (same path, same name), cut the 8.0.x tag from it, see driftwood's tool check pass on it, then park the rest.

## What the minimal loop must absorb

1. Keep the signing workflow at exactly `.github/workflows/cut-release.yml`, dispatched from `main` (or `release/X.Y.x`). Do not rename it and do not change the identity pattern, or edit the four driftwood copies in the same change.
2. Sign with `gitsign.rekorMode=offline` so the proof is embedded; verify in the same job with `GITSIGN_REKOR_MODE=offline gitsign verify-tag --certificate-identity-regexp=<anchored> --certificate-oidc-issuer=https://token.actions.githubusercontent.com` before pushing (the shape `cloud-release.yml:54-56` already uses), because a token-pushed tag will not trigger a second workflow.
3. Refuse a malformed tag (today's rule: exactly `vX.Y.Z` or `policy/vX.Y.Z`, `cut-release-normalize.py:34`); refuse a tag that already exists; push atomically; pass inputs through `env:`. If the cage keeps a `policy/` line, the shrunk workflow must accept that shape without the computed-semver gate.
4. Install gitsign by pinned version and sha256.
5. Replace the shift-left release gate with the target's own gate: run the consumer test / label-only negative control before signing, in the same place `release.yml:83-87` runs shift-left today. (The question's `proof.yml` does not exist in platform today; no current platform workflow runs any loop proof. That check is new work, not something carried from L16.)
6. Keep `LICENSE` and `.gitignore`. Replace `README.md` with a short front page pointing at the hub's `LOOP.md` and stating the release identity.
7. Stop `fetch.yml`'s cron, and remove the `recovery-expense.yml` triggers at the same time the composer is parked (it tests `compose/**`, so it would go red on the first push after the composer leaves).
