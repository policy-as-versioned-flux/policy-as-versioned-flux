# L07 Hub: twin, calibration programme, tests and benches (hub/twin/, hub/tests/, hub/bench/, hub/conftest.py, hub/pytest.ini, hub/bin/)

Verdict in one line: the loop runs without it. Nothing on the target's chain imports, reads or checks out this component. Four things outside it do depend on it (one live hazard, one identity helper, two tag pins), and about six rules in it must be copied into the new design. Recommendation: park.

All paths are under `scratchpad/fresh/` unless stated. Hub is `fresh/hub`, cloned 2026-11-14. Nothing was run, except `python3 /nonexistent.py` to read an exit code. "Park" means: leave the working tree and CI, stay in history, nobody extends it.

Size as I measured it (text files only): twin 171 files, 65,758 lines; tests 234 files, 61,078; bench 69 files, 14,520; bin 1 file. That is 141,356 lines, close to the brief's 143,516. The hub has 1,461 commits; 202 touch twin, 342 touch tests, 52 touch bench.

## 1. Attempt one: show the loop runs without it. SUCCEEDED.

The chain in the target is platform (loop, probe, inventory, cage v8, workflows), ico, feeds and driftwood. I looked for any way those read this component.

1. No Python on the chain imports `twin`. A grep for `^(from|import) twin` over platform, ico, feeds, driftwood, tuppence and ludlow (`*.py`, `*.sh`, `*.yml`) gives no hit in platform or ico. Hits elsewhere:
   - driftwood, tuppence, ludlow: `twin/emit-forward-intel.py` (`from twin import evidence, fixtures`, `twin.model`, `twin.repo`, `twin.schema`, `twin.valuation`; driftwood/twin/emit-forward-intel.py:98-101,212), `twin/verify-twin-scenarios.sh:43-45` and `verify-twin-overlay.sh:137`. These are the adopter's twin emitter and its own checks. The target's driftwood has no emitter.
   - feeds: `verify-news-headline-skill.sh:116-118` imports `twin.market_signals`. That script serves the market-moves/news feeds, which the target does not carry. feeds' release workflow says it is not run on a runner (`feeds/.github/workflows/release.yml:94-95`: "verify-news-headline-skill.sh is NOT run").
2. Platform deliberately has no dependency on the twin. `platform/fair/severity.py:6-14` says `twin/` is a package in the hub repo and `import twin.severity` "is not an import that can ever resolve" from platform; the engine carries its own copy and the seam is a JSON payload.
3. The price code already proves a missing twin is not an error. `platform/compose/composition.py:7750-7757` composes a driftwood copy with no `twin/` directory at all and asserts `outcome == "composed"` with no `source: twin` price ("a missing twin feed is never a refusal (ticket 25)"; also `:6609-6613`).
4. The twin's money does not matter to the one live adopter. In driftwood's committed `composed/evidence.json` the twin line `forward-intel` is £758.33 of a £1.79M feed line. The `agent-cage twin-agent` line is £0.00017. Removing both moves driftwood's figure by about 0.04%.
5. The twin is not the loop's compare or ratchet. Per H6: "No file here computes exposure, stores a tolerance, compares, ratchets or enacts" (maps/H6:71). H1: "No adopter calls [`pricing.price()`]" (maps/H1:7); no tolerance is read anywhere in the twin (H1:11). `twin/enact.py:229` has no PR-opening or apply path (H3:9), and the invariant `no_recommended_action_field` forbids the twin recommending a ratchet by design (H6:80).
6. No workflow on the chain runs hub tests or benches. The tests and benches are exercised only by hub's own `twin.yml` (`pytest`, `bin/twin verify`, the Linux lease jobs) and by hub's truth gate.
7. Calibration programme: about 49k lines (qualification, reference cases, Xpdf comparison, ELF closure, Linux lease) with an empty registry and no operational caller (maps/A5, H5:8, H5:72). It cannot feed any loop step.

So a loop with this whole component absent runs exactly as the target's loop would.

## 2. Attempt two: show the loop breaks or loses something. PARTLY SUCCEEDED. Nothing in the loop breaks. Four non-loop things break, and some knowledge is lost.

The same step is in `tuppence/.github/workflows/twin-sweep.yml:117` and `ludlow/.github/workflows/twin-sweep.yml:117`.
   - **`platform/.github/workflows/cloud-release.yml:23-26`** also checks out `twin/v0.1.0` into `_hub` ("Pin the dependency tree") and runs `implementations/cloud/release_check.py --hub _hub --record`. A test pins it: `platform/implementations/cloud/test_trigger.py:177`. This is a dispatch-only workflow and the platform cloud package is not in the target, but it is a second reason the tag must stay fetchable. The question did not list it.
   - A tag lives in git history, so parking the working tree does not remove it. What would break it is deleting the tag, or making the hub private or archived in a way that stops an unauthenticated cross-repo checkout. Could not determine whether the hub is public (the checkouts use `persist-credentials: false` and no token, which only works for a public repo).
   - Until the three emitters are parked, their daily sweeps keep working. Once each adopter's `twin-sweep.yml` is disabled, the pin is unused.
2. **`.claude/settings.json` hook points at `twin/enact_guard.py`** (`hub/.claude/settings.json`: `"command": "python3 \"$CLAUDE_PROJECT_DIR/twin/enact_guard.py\""`, matcher `.*`, PreToolUse). The guard is already a no-op (`twin/ENACT_MODE` reads `development`; `decide` returns None for everything, H3:12). The fix is to remove the hook and the file in one commit. The target's loop makes "a person merge" the proposals, so the loop does not need it. But the merge identity does. Whatever happens to `twin/`, this file must move out first, or the merge procedure breaks.
4. **Hub's own gates.** `.github/workflows/twin.yml` runs on `twin/**` and `tests/**` pushes and a daily cron (`17 5 * * *`). It runs `sudo` for up to 17 minutes on the Linux lease rows (H5:96). `truth.yml:43` watches `twin/ENACT_MODE` and `ENACT_MODE.why`. The verify scripts import from twin: `verify/model-permission/verify-model-permission.sh:94,422`. If the working tree is trimmed the daily cron and these gates go red or fail to find files. Parking should switch the cron off first.
5. ## 4. What the minimal loop must absorb

1. **Infra is a role, not a rung; an unclaimed pod is outside the cage.** (`tests/test_cage_ladder_holes.py:1-60`, ADR-0022, ticket 113.) A pod in `kube-system`, `flux-system` or `kyverno` must not be caged by the ladder. A claiming pod in an ungoverned namespace took the ungoverned else-branch, which was `baseline`, the loosest rung, under 4.0.0. Cage v8's two bodies and its consumer test must state, and test, what happens to a pod in a namespace with no rung label. That is also the `serving-lost` risk, because a bundle that refuses the pod looks like a cage.
2. **Pin the engine: Kyverno 1.18.2.** The ladder-hole test says 1.19.1 "refuses to compile the served body at all (`expected type 'string' but found 'dyn'`)" and that grading with another CLI is could-not-look (lines 52-56). Memory `feedback_kyverno_pin` agrees. Cage v8's consumer test must pin the engine and treat a different one as could-not-look.
3. **Two governed Namespaces for one party is could-not-look, not a pass.** A party that declared two governed Namespaces made the binding walk print SKIP and exit 0, so the gate read PASS for an unobserved cage (lines 40-50, ticket 114). The target has one Namespace; the probe's "pods observed at the last commanded rung" rule should exit non-zero on "cannot say which rung applies", never on a skip.
4. **A skip must never read as a pass.** The 2026-09-04 and 2026-09-09 commits are the same lesson three times. It is the same as NO MEASUREMENT, NO MOVE; the ledger line must print `could-not-look` rather than omit a figure.
5. **A missing instrument refuses; do not invent.** `twin/valuation.py` refuses an unmatched FX date; ADR-0020 is the rule. In the target, ico and feeds are single-currency GBP, so this only applies if FX returns. Say so in LOOP.md.
6. **Do not copy the twin's "unpriced when evidence is weak" rule.** The twin refuses to price a path whose evidence grade is above 2 (`pricing.py:228-287`, H6:73) and credits zero for grade 5. Crediting zero for weak evidence agrees with "only a measured closure may lower the figure". But leaving weak evidence unpriced lowers the figure. The target says the opposite: an unsourced number may raise it, and a missing number makes a lower bound. Absorb the target's rule, and note that it reverses the twin's.
7. **Split the measuring job from the writing job.** The sweep was one job running the hub's code under `contents: write` with the hub checked out at `main` (twin-sweep.yml header: ticket 143, ADR-0031 point 4). It now runs a read-only job and a writer job, with the code pinned to a full commit, and the hub checkout verified against `hub_commit`. The target's reusable loop workflow reads the cluster and then writes the rung line and the ledger line. Keep a read-only measuring job, hand one artifact to a writer job, and pin the loop code by tag.
8. **A clock may append observations and propose; only a reviewed change enacts.** (twin-sweep header, ADR-0024, D1.) The target already says this ("a person merges").

Not worth carrying: the evidence ladder, FAIR/PERT-with-causal-graph pricing, the 11 firm models, forecasting, scoring, qualification, the Linux lease cage (it cages the assistant's helper, H5:59), loophole rounds, the invariant manifest's hash-pinned authorisation ceremony.

## 7. Recommendation: park

- Not keep: 141k lines for no loop step, and an October programme with no caller.
- Not cut: three live pins and one live import (items 1 to 3 above) would break, and the tag cannot be re-cut (it is signed, and the cut identity and hub commit are anchors in `driftwood/twin/PIN.yaml`).
- Not shrink or merge as a whole: the useful parts are tiny and are not twin code. They are lessons (section 4), plus one 171-line file.

Order of work, if the owner approves later (nothing is done now):

1. Switch off the three adopters' `twin-sweep.yml` and hub `twin.yml`'s cron.
2. Remove the PreToolUse hook entry and `enact_guard.py` in the same commit.
3. Move `twin/other_hand.py` (or a copy of its 171 lines) next to `truth-delivery.yml`, so the merge identity does not live in a parked package.
4. Copy section 4 into LOOP.md and ADR-0039.
5. Leave the tag `twin/v0.1.0` untouched.
6. Say in LOOP.md that tuppence's and ludlow's twin lines are parked with them.

Confidence: high on "the loop runs without it" and on the four dependents. Medium on how the hub's own gates would behave once trimmed (I did not run them).
