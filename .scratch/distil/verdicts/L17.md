## Attempt 1: does the loop run without it?

It does not. Every step of the loop that touches the adopter reads a file in this component.

- **T (tolerance).** The only declaration is `driftwood/party.yaml:60` (`tolerance: { amount: 40000, currency: GBP }`). The reader is `platform/risk/enforce.py:57-62` (`party_yaml_path` resolves `<estate>/<org>/party.yaml`). The schema makes `appetite.tolerance` required (`platform/party/schema.json`, `appetite.required == ['tolerance']`). Without it there is nothing to compare against.
- **Q (quantify).** The penalty term scales with turnover, at `party.yaml:43`. The feed pins the composer prices against are `party.yaml:66-80`, plus `gitops/flux-system/gotk-sync-{ico,feeds}.yaml`. These are read by `propose-tier.yml:168-173` (`read-pins.py`) and checked by `propose-tier.yml:219-224` (`verify-pinned-checkouts.py`). `cut-release.yml:59-63` and `:117-121` read the same files.
- **R (ratchet).** The rung is one line, `gitops/apps/namespace.yaml:30`. The writer is `platform/wargamer/tier_pr.py:328` and `:1051`, which edits the governed Namespace document.
- **E (enact).** The cage reads the rung from the Namespace alone (`composed/policies/v7.0.0/cage-tier.yaml:31-34`). It matches only pods that claim `7.0.0` (`:25-29`). The workloads it cages are `gitops/apps/{storefront,api,pod}.yaml`. Flux reaches them through `gotk-sync.yaml:56` (`path: ./gitops/apps`). The cage itself arrives through `gitops/composed/composed-set.yaml`, which `drift-sample.yml:239` applies. The engine pin is `gitops/engine/kyverno.yaml`, read by `shift-left.yml:124` and `drift-sample.yml:127`.
- **X (react).** `renovate.json` is the only thing that bumps parent pins. Its nine regex managers target `gotk-sync-*.yaml`, `platform-pin.yaml` and `party.yaml`'s feed lines. Its one recorded merge was PR #20 (`ea1c8db`, 2026-09-01).
- **The target's own loop needs the same files.** Its loop reads tolerance from party.yaml, rewrites the one rung line, probes the workload's own pods, and is fed by Renovate pin bumps. All four live here.

Conclusion: attempt 1 fails. No reading of the chain, today's or the proposed one, gets by without a declaration of T, the rung, the caged workloads, the Flux route and the pin bumper.

## Attempt 2: what breaks or is lost without it

This attempt succeeds. Rules and fixes that exist only in these files:

1. **Cage before workloads.** `gotk-sync.yaml:37-45`, commit 8d9ae2e. The apps Kustomization `dependsOn` the composed policy Kustomizations. Admission fires once (`cage-tier.yaml:20-22`, CREATE and UPDATE only). Without the ordering, a cold cluster admits pods before the cage exists, and they are never re-caged.
2. **Workloads that actually start.** Commit 1951262 (`deploy/pod.yaml:26-37`, `gitops/apps/pod.yaml:34-40`). `runAsNonRoot: true` on plain nginx made the kubelet refuse to start the container. The fix is `runAsUser: 101` plus emptyDirs on `/var/cache/nginx` and `/run`, keeping `readOnlyRootFilesystem`. This was carried to storefront without being observed (`storefront.yaml:49-53`).
3. **An explicit `namespace: driftwood` on every manifest.** `gitops/apps/pod.yaml:27-33`. Without it Flux applies the pod into `default`, outside the cage.
4. **`path: ./gitops/apps`, not `./apps`.** `gotk-sync.yaml:48-56`. A run reported `kustomization path not found` (run 34122734820).
5. **Every workload claims a policy version.** Each manifest carries `policy-as-versioned.dev/policy-version: "7.0.0"`. The cage matches only that version (`cage-tier.yaml:28-29`). A cage-major bump that does not move the claims in the same change leaves pods caged by the wrong version, or by the orphan cage.
6. **Renovate rules.**
   - `enabled: false` silences the hosted app. The self-hosted run force-enables itself (`renovate.json:3-4`, commit fc1a252). Two Renovates had fought over one branch.
   - `tag:` and `commit:` must be on adjacent lines for the regex (commit 8bf8e48).
   - The native Flux manager cannot keep a {tag, commit} pair (`renovate.json:16`).
   - `rangeStrategy: pin` (`:147-155`).
   - Commits go by git push, not the API (`platformCommit`, commit b7f9088).
7. **Two owners of one name.** `platform-pin.yaml:48-52`. Installing platform's distribution beside the composed set rendered two cluster-scoped `policy-version-orphan-guard` objects, and the last apply won. That is why `drift-sample.yml:225-230` applies `platform-pin.yaml` only.
8. **No `spec.verify` on gitsign tags.** Flux's verify speaks only OpenPGP. Identity is pinned through annotations instead (`composed-set.yaml:30-38`, `gotk-sync-ico.yaml:23-27`).
9. **Engine pinned by version and sha256.** `gitops/engine/kyverno.yaml:39-46` pins 1.18.2.
10. **Disclaimer.** "A demonstration party, not affiliated with ... any real authority it names" (`party.yaml:1`, `README.md:6`, commit 18c6416). The estate names a real regulator, so the disclaimer must survive.

## Hazards the check does not name

- **Stamp key.**
  - The cage writes `posture.acme.io/tier` and `posture.acme.io/caged` onto each pod as output (`cage-tier.yaml:40`). The manifests say a tier declared on a pod "would be clobbered" (`pod.yaml:23-25`).
  - If the template stamp uses that same key, a pod admitted with no cage would still show the rung. A "pods observed at the commanded rung" check could then pass on a label alone.
  - The template stamp needs its own key. The settle check must read a mark only the cage writes.
- **Following `main` breaks today's inventory proposer.**
  - `platform/wargamer/inventory.py:55-66` raises `InstrumentFault` unless `gotk-sync.yaml` declares exactly one GitRepository pinned to a tag and a full commit.
  - It also drops the signed-tag provenance described at `gotk-sync.yaml:3-8`.
  - `hub/verify/lifted-apps/verify-lifted-apps.sh` reads the self-pin too.
- **Deployments and today's readers.**
  - `drift/served_apps.py:98-102` accepts only `kind: Pod` and raises "the signed apps source carries no served Pod".
  - `platform/shift-left/ci-check.py:88` reads top-level `metadata.labels`, which on a Deployment is not the pod template.
  - So "a Deployment would be graded by nothing" (`storefront.yaml:34-36`) is a limit of these offline readers. Admission works on pods, and a ReplicaSet creates pods, which the CREATE rule matches. That is reasoning, not something I ran.
- **Schema sequencing.**
  - `platform/party/schema.json` requires `overlay` with `add` and `restate`. `party_artefact.py:196-203` and `:266-274` enforce it, and `shift-left.yml:117` runs it on every pull request.
  - Removing `overlay` while shift-left still runs fails every pull request. Removing just `floor` passes, because it is optional.
- **Renovate's post-upgrade task.** It calls `complete-feed-bump.sh`, which re-renders `composed/**` and `twin/**` (`renovate.json:136-146`). Once those are cut, the task must go in the same change, or every bump fails.
- **The loop's one-line rewrite fails closed.** A corrupted rung label puts every pod at `isolated` (`cage-tier.yaml:34`), and `isolated` is a deny-all network rung. The serving check must catch this.
- **The cage-version claim moves with the cage major.** See attempt 2, item 5.

## Recommendation: shrink

**Keep a small named part.** About 300 authored lines, plus LICENSE as boilerplate.

- `party.yaml`: size, tolerance with a basis line, the ico, threat-register and cve pins, and the disclaimer.
- `gitops/apps/`:
  - The Namespace: governed label, the one rung line, and the prune guard.
  - The three workloads, rewritten as Deployments. They keep the `runAsUser: 101` and emptyDir fix, explicit namespaces and the version claim.
  - The template stamp, under a key of its own.
- `gotk-sync.yaml`, keeping `path: ./gitops/apps` and `dependsOn` the cage.
- `gotk-sync-ico.yaml`, `gotk-sync-feeds.yaml`, `platform-pin.yaml`.
- A cage install by signed platform tag, replacing `composed-set.yaml`, with one installer only.
- `engine/kyverno.yaml`.
- `renovate.json`, cut to the needed managers. It keeps `enabled:false` with the self-hosted force, adjacent tag and commit, and `rangeStrategy: pin`.
- README cut to about 20 lines.
- LICENSE.

**Remove, in the cut-over change and not before:**

- `deploy/pod.yaml`, with shift-left.
- The two ConfigMaps.
- The nist, insurer and fx pins.
- `platform-distribution.yaml`.
- `assurance_bands`, `pricing_threshold`, `baseline`, `publishes[]` and `workload_cages`.
