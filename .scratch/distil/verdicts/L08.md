# L08 Hub: truth surface and CI (hub/verify/, hub/talk/, hub/.github/, hub/tts.py, hub/clone-estate.sh)

Read-only check, 2026-11-14, against `fresh/*` clones. Paths are `repo/path:line`. "Gate" means the daily truth run that executes the hub's verify scripts and prints one TRUTH line.

## Verdict in one line

The proposed loop runs without this component. The one live pin into it (driftwood's record-delivery workflow) reaches a single commit, and that commit stays reachable if hub history is kept. What would be lost is a set of hard-won habits for writing a daily record safely. Those habits are small and must be carried into the platform loop's workflow and tests. Recommendation: park, with the daily schedules turned off.

### What lives only here (lessons, with the evidence)
1. Three-outcome rule and its self-test. `hub/verify/lib-observation.sh:1-30,64-90`: a check never prints PASS when a live tail could not look; exit 3 with a SKIP last line; `selfcheck_absent` re-runs the script with the tool hidden and requires exit 3. `hub/verify/every-green/every_green.py` scans all 151 scripts for a SKIP token followed by exit 0 (ticket 76). The platform copy covers shell checks, but the new loop.py has no equivalent test yet in these trees: `find fresh -name 'test_loop*'` finds no platform test (the target's `test_loop.py` is not built). The rule must be rewritten as a loop test, not assumed.
2. A wait that asks before the answer can exist, and takes silence for yes. `hub/verify/sampler-wait-order/verify-sampler-wait-order.sh:1-30`: three rounds (2026-09-01, 09-04, 09-09) sampled a cluster before the generated Kustomizations existed, enumerated nothing, returned in 0.3s and recorded "applied" facts. Direct bearing on the target's "settled pods" and reference-pod bracket: an empty pod list or empty enumeration must be could-not-look, never "all settled" or "all closed".
3. Writing the daily record safely (`hub/.github/workflows/truth.yml:81-91,174-183,205-237`):
   - Record only on the default branch. Runs 92, 95, 98 had the push refused after a rebase; runs 100 and 101 landed on a merged branch; runs 76, 84, 88 were orphaned unnoticed (ticket 100).
   - Concurrency by event and ref with `cancel-in-progress: false`: a scheduled run queued behind a push was cancelled before recording, and the old checker graded the cancel PASS (observed 2026-09-04).
   - `!cancelled()`, not `always()`; a cancelled run must not record.
   - A clock never grades its own run (commit 75d6015d).
   - `fetch-depth: 0` (commit 5d462f89 "The estate clone stops being shallow") and `persist-credentials: false` where unpinned third-party code runs; keep the credentialled read job apart from the job that runs other code (ticket 56).
4. Pin the instrument. truth.yml:61-69: an unpinned `latest` Kyverno download silently became 1.19.0 and reddened three checks for two runs (commit db47f885). Estate pin is 1.18.2; the memory note says 1.19.1 will not compile the served body. The platform harness and probe must pin Kyverno (and Flux, truth.yml:74-77) and print the version.
5. Where a clock can write. `hub/.github/rulesets/README.md:20-30`: GitHub refuses the Actions app as a bypass actor (HTTP 422), and public repos cannot enforce lane paths. So a branch a clock pushes to cannot carry a pull-request rule. This is why the target's ledger must sit on its own branch (not main) and why the release proposal PR needs the org's "Actions may create PRs" setting (memory: enabled 2026-08-15). The four ruleset JSON files (main-is-reviewed, main-keeps-its-history, release-branches-are-reviewed, release-tags-hold) exist only here as text; the applied state lives on the forge.
6. Owner doctrine "deny is not a rung" (`hub/verify/deny-is-not-a-rung/README.md:1-10`, owner 2026-09-02, ticket 75 Q5: "something could find itself unable to run ... not because we deliberately deny it"). Target text already says "Never a deny" and `serving-lost` opens a release proposal. The scanner (1,026 lines with register) is not needed; a 20-line test over the cage bodies that fails on `validationActions: Deny` or `validationFailureAction: enforce` would carry the rule. Note the register still shows 12 served copies carrying a declared Deny (SKIP in run 491), which is a live inconsistency with the doctrine, not something the loop can use.
7. Clock lateness. Memory: first firings had about 5 hours cron delay. The target's 10-minute could-not-look limit is per run, not per cron. The schedules check (`hub/verify/schedules/`) is where this was learned; the ledger needs a dated window, not a time-of-day expectation.

## What the minimal loop must absorb (carry over)
1. A loop test: probe unreachable, reference pod failed, no pods found, or feed unreadable gives could-not-look, never `within` and never a pass (the survivor of lib-observation and every-green; the question says it survives in test_loop.py, which does not yet exist in any clone).
2. Treat an empty enumeration as silence, not yes, in probe.py and in the settle wait; wait for generated objects, not only applied ones (sampler-wait-order).
3. In the loop workflow and ledger writer: write the ledger only from default-branch runs; per-ref concurrency with no cancel-in-progress; skip recording on cancel (`!cancelled()`); never grade its own run; `fetch-depth: 0`; `persist-credentials: false`; keep the credentialled job apart from any job that runs code from another party.
4. Pin Kyverno at 1.18.2 (and Flux) in the harness and the probe, and print the version on every ledger line.
5. Ledger on its own branch, because an Actions identity cannot bypass a main review rule on these orgs; release proposals need the Actions-create-PRs org setting.
6. A small test that no cage body carries a deny-shaped action (deny-is-not-a-rung doctrine, owner 2026-09-02).
7. Keep the four ruleset JSON files somewhere the owner can reapply them (hub history is enough if the tree is parked; copy two lines of intent into LOOP.md otherwise).

## Recommendation: park
- Leave `hub/verify`, `hub/talk`, `hub/.github` (rulesets, cut-release, release), `tts.py`, `clone-estate.sh` in the working tree and history. Do not rewrite hub history: driftwood, ludlow and tuppence fetch a commit by SHA.
- Turn the schedules off on `truth.yml` and `truth-delivery.yml` (dispatch only). Without that the "no bot commits" claim is false and the gate goes red as neighbours simplify.
- Keep `observation-delivery.pyz` at f546d2d9 reachable; keep tag `twin/v0.1.0`.
- Do not "keep" (as is): 69,717 lines grade documents, records and each other (H7: 69 percent), and the daily number has not moved for 13 runs.
- Do not "cut": the working tree is cheap to leave, and the pin, the twin tag, the cloud release and the lessons above still point at it.
- Not "merge" as a whole: the useful part is seven small rules, listed above, that belong in platform's loop workflow and tests, not in a file moved wholesale.
