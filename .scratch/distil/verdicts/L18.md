Paths: `driftwood/drift/`, `driftwood/git-server/`, `driftwood/kind/`, `driftwood/scripts/`. All citations are to the fresh clones taken on 2026-11-14 (`scratchpad/fresh/<repo>`), unless marked otherwise.

Terms used below:
- **could-not-look** (also "unmeasured"): the instrument's third verdict, `observed: null`. It is never a pass.
- **fall-closed pod**: the probe pod placed in a Namespace that is governed but names no rung. The cage's fall-closed rule should put it on the tightest rung.
- **reference pod**: a pod the cage does not select. Its working network is what makes a caged silence mean something.

### What is lost: the measuring discipline the target's FEEDBACK step depends on

The target prices exposure "from this cycle's probe, never from the rung in git". It also brackets every network probe with a reference pod. This component holds the reviewed bracketing code.
- **Copies.** tuppence and ludlow carry near-copies of `five-facts.py`. A grep for `_cage_silence_persists`, `reference_before` and `conditionStatus` across `platform`, `tuppence`, `ludlow` and `hub` (outside `.scratch`) finds the bracket only in the three adopters' `five-facts.py`. `hub/verify/cloud-plane` matches `conditionStatus` for an unrelated purpose.
- **The platform's older check.** `platform/graded/verify-graded.sh:616-664` polls `nc` from an isolated pod for up to 60 seconds. It has no reference read before or after.
- **So**, among what the target keeps, the rules live only here. Their other copies sit in the two adopters being parked.

The rules below are the fixes. Each one closes a false green that was observed live or reproduced over the real function.

1. **Bracket, and require the silence to persist.** The reference is read first, then the caged pod, then the reference again (`five-facts.py:972-979` design, `:1062-1114` code). The caged silence must hold across `CAGE_SILENCE_READS + 1 = 4` reads, 3 seconds apart (`:197`, `:918-955`). Commit `35e46ee` (2026-09-10, F-02) found the old order scored "a cage that held" for any outage clearing between exec 3 and 12. The live green had `seconds_waited_for_the_cage: 0`. The last real record (`samples.jsonl`, 2026-11-13) has `reference_before`, `reference_after` and `seconds_waited_for_the_cage: 18`. **Target rule protected:** only a measured closure may lower the figure.
2. **A pod the cage never stamped is not evidence.** `_cage_touched` (`:608-626`) requires `posture.acme.io/tier` or `caged=true` on the live pod. In `35e46ee` (F-03), fact 6 went TRUE on a live cluster whose cage matched nothing. **Protects:** "every governed pod observed at the last commanded rung". The target's probe "reads the rung on every pod", and this is how that read must be done.
3. **Installed is not serving.** `cage_in_force` (`:463-482`) needs Kyverno's `status.conditionStatus.ready`. A policy that has landed but has no webhook yet admits pods unmutated. **Protects:** "a cage that failed to arrive leaves the figure up".
4. **`kubectl exec` exit 1 is ambiguous.** It means both "the command failed" and "the command never ran". The real exit code is read from a marker in the pod's stdout (`:592-605`). An unrunnable connect is could-not-look, never "closed". **Protects:** no measurement, no move.
5. **Unsettled is not a verdict.** `ContainerCreating` and `PodInitializing` are transient (`:191`). An unscheduled pod reflects the runner's capacity. An apply with no pod behind it refused nothing (`_cage_admission_verdict`, `:629-656`). **Protects:** "pods not settled: could-not-look".
6. **The reference must be outside the cage.** If the cage stamped it, or a NetworkPolicy selects it, the comparison is void (`:1027-1051`). A broken network silences both pods, and that reads unmeasured (`:1062-1077`, `:1104-1114`). **Protects:** "a reference that worked".
7. **A NetworkPolicy with `matchExpressions` is not match-all.** It is skipped. A silence that no evaluable policy explains is not credited to the cage (`:572-573`, `:1116-1121`).
8. **Same node for the reference copy.** `served_apps.py:61-68`: copies on different nodes cannot isolate the cage's effect, and two stopped workloads do not show a cage fault.
9. **Two connect targets cannot tell the middle rungs apart.** "every hardened rung reaches neither of fact 7's targets" (`:677-678`). Bottom is derived from the lowest `cage-` PriorityClass and from a rule-free deny-all (`:674-730`). **This matters for `rungs.yaml`:** if a rung claims to close a capability, the probe must have a target that tells that rung from its neighbours. Today restricted and quarantine generate the same NetworkPolicy: `cage-netpol.yaml:40-45` maps every rung but `isolated` to one shared `'other'` reach (`driftwood/composed/policies/v7.0.0/`). Commit `668f1d3` adds an ordering rule: ask whether a distinct bottom rung exists *before* any connect.
16. **A FALSE is never laundered into a could-not-look.** In `cd0a61e` (2026-09-10), `grade` built its verdict with `max(verdict, 1)`. So once any earlier fact was a could-not-look (3), every later observed FALSE also reported as 3. It was measured on main: three FALSE fact-5 lines graded as "could not look" on every citable run since 2026-09-09. **Protects:** "ends red every cycle". The target's verdict must rank red above could-not-look.
10. **The WAF sidecar image exists in no registry.** Without a stand-in, every hardened pod sits in `ErrImagePull`, and you measure the registry, not the cage (`five-facts.py:758-762`; the stand-in build is in `drift-sample.yml:66-74` and `:183-186`, outside this component). The target's cage v8 must either drop the sidecar or ship an image that exists.
11. **Clean-up must wait for deletion and confirm absence** (`e53defa`, 2026-10-23, `:883-897`). A failed clean-up is kept as evidence and never discards a measured FALSE.
12. **Kyverno CLI quirks for the platform consumer test** (`cage_probe.py:28-35`, `:13-16`):
    - On 1.18.2 the result table reports a GeneratingPolicy as passed when it generated nothing, so judge by the objects written.
    - The CLI reads Namespace labels only through a Values-file `namespaces:` list.
13. **API-server defaults are not drift.** An omitted `globalDefault: false` on a PriorityClass is equal (`ce614b2`, `render_composed.py` `omitted_zero`). This matters only if the target ever compares live objects with rendered ones.
14. **Release identity must be anchored** to org, repo, workflow and ref. It is proven against real gitsign tags and checked with synthetic negatives (`scripts/verify-identity-regexp.sh:1-21`; commits `e23be9b` and `325b854`, cs-14). The target keeps a signed release in platform. The script sits here because it was written for driftwood's `release.yml`.
15. **Laptop harness: restart the git server after a reseed.** An unchanged image tag left the kubelet serving the old seed, and Flux could not resolve the new commit (`1e10b44`, `scripts/up.sh`). The target has "a laptop harness" in platform.
