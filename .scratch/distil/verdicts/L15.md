## Attempt 2: the loop breaks or loses something

I found no break in the target. I found six lessons, five of them encoded here and nowhere else, that the target's workflows and tests will need to relearn if they are not carried over.

### Lessons that live only here (and where)

1. **Release tags must embed their Rekor proof, or the identity-pinned verify fails offline.** `verify-release-signing.py:1-89` (commit 341bd4c, 2026-10-17, "Embed Rekor proofs when signing platform release tags"). It runs the real signing calls of `cut-release-create-tags.sh` and the cloud-release step with a stand-in signer that refuses, and asserts the config at the signing boundary is `gitsign.rekorMode = offline`. The fix itself is in `.github/scripts/cut-release-create-tags.sh` and `cloud-release.yml:50-55`, which stay. The test that guards it is only here. It is called only from `verify-cut-release-tags.sh:21`.
2. **The identity regexp must be anchored at both ends, escape every dot, and accept `release/N.N.x`.** `verify-certificate-identity-regexp.sh:1-45` (cs-14, 2026-08-22). It reads the pattern out of `release.yml` and rejects foreign org, repo, workflow path, `mainX`, and a prefixed URL. The pattern itself is at `release.yml:56`. driftwood has a copy in its own workflow (`driftwood/.github/workflows/verify-identity-regexp.yml`) pointing at `scripts/verify-identity-regexp.sh`.
3. **Could-not-look is a third outcome, not a pass and not a fail.** `lib.sh:1-30` and `lib-selfcheck.sh` (2026-08-28, 2026-09-04: "kyverno-absent is could-not-look, not a green", "a skipped live tail makes the script SKIP, exit 3"). The target's NO MEASUREMENT, NO MOVE is the same rule written for the loop. `lib.sh` is sourced by 47 files; the ones outside L15 that the target may keep are `graded/` (1), `distribution/` (3), `engine/` (1), `compose/` (10), `computed-semver/` (12), `wargamer/` (3). If graded and distribution tests survive into cage 8, `lib.sh` is a hidden dependency.
4. **A cage body that mutates a container list must not run on UPDATE.** `distribution/cage_body.py:170-215` explains why, and names `currency-controller/currency.py recage_patch()` as the object the rule protects. Three real instances: a sidecar appended twice rejecting every update (ticket 26, 2026-08-28), a PriorityClass no cluster has (ticket 89), the UPDATE cage trying to append to an immutable list. The rule lives in `distribution/`; the working demonstration lives in `currency-controller/`.
5. **Admission is a snapshot.** `currency-controller/README.md:14-18`: "Both fire once, at admission, and never again... Nothing else in the estate re-evaluates it." A running pod keeps the rung it was admitted with. This is the same fact map A4 calls break (e) of ENACT. The target's answer (workloads as Deployments stamped with the rung, and `probe.py` reading the rung on every pod) is stronger than the controller, because it observes rather than assumes. The controller re-cages only on a retired version, which the target no longer has.
6. **`cage-tier` clobbers the tier label on CREATE and UPDATE**, so writing the label alone is undone by the admission it triggers (`currency-controller/README.md:42-48`). Relevant to any harness that "hand-loosens" a pod label to test correction.

Lesson 3 has an echo in policy: the owner's 2026-09-02 doctrine is that something may be unable to run because it does not fit the cage, but nothing is deliberately denied (`hub/verify/deny-is-not-a-rung/register.yaml:6-9`). `platform/policy/README.md:28` ("Deny - bottom rung, it does not run") and `:66` ("or it does not run") contradict that and the target's "Never a deny". I found no gate that reads that README prose; the hub register scans served policy copies. The wording leaves with the directory, as the task says.

## What the minimal loop must absorb

Rules, not code. Each is cheap to carry.
1. Signed release workflow: embed the Rekor proof when signing (`gitsign.rekorMode=offline`), verify with `GITSIGN_REKOR_MODE=offline`, re-fetch the annotated tag object after checkout, anchor the identity regexp with `^...$`, escape dots, allow `main` and `release/N.N.x`, and keep the `workflow_dispatch` fallback because a `GITHUB_TOKEN` push does not chain-trigger another workflow (`release.yml:17-21`). Carry them as one test of about 130 lines: `verify-release-signing.py` (89) plus the regexp check (45).
2. The loop's own verify step: `loop.yml` (or the caller) verifies the platform tag with `gitsign verify-tag` against a pinned identity before it trusts a pin. Copy `propose-tier.yml:97-147` and drop the `adopter-gate.py` dependency.
3. Could-not-look as a first-class result: keep `lib.sh` (102) and `lib-selfcheck.sh` (44) for as long as any retained shell proof sources them, then retire it when the target's NO MEASUREMENT, NO MOVE is a code path with its own test.
4. A cage-8 test that a mutating body does not run on UPDATE and that admission leaves a running pod unchanged. Today this knowledge is in `distribution/cage_body.py:170-215` and `currency-controller/README.md`. The target's "negative control with a label-only change lowers nothing" already tests the second half. Add the first.
5. The Kyverno 1.18.2 Excluded-row trap (from L14) applies to cage 8's namespace-selector bodies; not in L15 but adjacent.

## Verdict

**Attempt 1 succeeded; attempt 2 found lessons, not dependencies.** The loop runs without this component. What would be lost is a set of guards and observations the loop does not read, plus six lessons, five of which are in tests and comments here only.

**Recommendation: shrink.** Park about 17,400 lines (every directory in the list, the four large root verify scripts). Keep a named part of about 280 lines: `verify-release-signing.py`, `verify-certificate-identity-regexp.sh`, `lib.sh`, `lib-selfcheck.sh`, folded into the new signed-release proof. Leave nothing deleted in this pass; park means out of the working tree and CI and in history.

Two parts carry owner decisions and should be parked by name, not dropped silently: `currency-controller` (kept by ticket 75 Q13 because it is the only post-admission re-cage; the target supersedes it with probe-and-stamp, which needs the owner to say so) and `recovery-expense` (owner-adopted 2026-10-23 for a pilot that starts 2027-01-01; parking it ends that pilot before it begins; the owner decides). `identity/gitsign-verifier` should go only after `loop.yml` verifies tags in CI and the owner confirms the vendored-bodies delivery route.

Confidence: high that the loop runs without it; medium on exactly which retained shell proofs still source `lib.sh`, and on the cage delivery route (could not determine).
