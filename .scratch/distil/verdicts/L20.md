# L20 verdict: driftwood CI (`driftwood/.github/`, 6,718 lines)

Verdict in one line: the target loop runs without about 6,650 of these lines. It does not run without the directory itself. The target's 25-line caller has to live here, and Renovate only runs here, because `renovate.json` switches itself off and the runner in this directory switches it back on. Today's chain cannot lose any of it yet: this directory holds the only quantify that runs (06:47), the only daily look at the cage (06:20) and the only trigger from a publisher's side (06:11). Recommendation: **shrink**. Keep a new caller and a cut-down Renovate runner, about 65 lines. Park the rest after the cut-over, in the order set out in section 5.

They also number the decision differently: `the-room.md:168` asks whether the ratchet runs one way only, while `TARGET.md:416` asks who merges a tightening. The task follows the second. Terms used here:
- A **required check** is a status that GitHub's branch rules must see pass before a pull request can merge.
- **Required review** means a pull request needs an approval before it can merge.
- **GH013** is the error GitHub returns when a push breaks a repository rule.
- The **default token** (`GITHUB_TOKEN` or `github.token`) is the credential each workflow run is handed.

## 4. The five checks the task names

1. **"The old gates are removed before the PR that resets the rung and moves the pins, because they would refuse it."** Confirmed from code.
   - Tier binding fails a Namespace tier looser than the strictest priced line clamped to `overlay.floor` (`shift-left.yml:507-557`). The reset loosens from `isolated`.
   - Compose-check recomposes and fails on any change under `composed/` (`:480-505`). Moving the pins without recomposing fails. So does recomposing after `composed/` has gone, because compose writes it back.
   - The adopter gate refuses a platform major with no acceptance record (`:198-234`; 8874bc0, ticket 132). Cage v8 is a major move from v5.0.0.

   One ordering trap: the PR that removes compose-check must also remove `composed/` (L19) and edit `renovate.json` `postUpgradeTasks` and `fileFilters` (`renovate.json:136-145`). Otherwise the next Renovate bump runs `complete-feed-bump.sh` and recomposes a tree that no longer exists.

2. **"If any is a required check, an admin changes the rules first."** Whether they are required: could not determine, because the live settings cannot be read from a clone. Here is what can be inferred, labelled as inference.
   - Required review is in force (ADR-0037:11-13, and only App merges on first-parent `main` since 2026-10-16).
   - The daily observation PR is opened with the default token (`drift-sample.yml:391`), so by rule 6 no `pull_request` workflow runs on it, and `shift-left` never reports there. The App still approves and merges it every day (`hub/talk/observation_delivery.py:622-637`), and ADR-0037:39 says it has "no … main-rule exception or bypass".
   - Together that suggests `shift-left` and `compose-check` are **not** required checks. It is still inference. A person with admin rights should look for the contexts `shift-left` and `compose-check` before the cut-over.
   - The push ruleset in `rulesets/observation-lane.json` was never applied, because the repository is public (`rulesets/README.md:13-23`; capture `hub/talk/captures/verify_schedules_verify-schedules.out:11`).

3. **"The loop gains its write path only after the old schedules stop."** Confirmed, with one sharper point. `propose-tier.yml:44-50` also fires when a PR that touches `party.yaml` or `gitops/platform/platform-pin.yaml` is merged, and the reset PR touches both. Which version of the workflow file GitHub runs on that event cannot be told from a clone. So stop the old clocks in an **earlier** PR than the reset, not the same one.

   The clocks to stop are `propose-tier`, `renovate-run` (its old post-upgrade task), `drift-sample`, `twin-sweep` and `observation-delivery`. Otherwise a tighten-only proposer sits beside a loop that can release: `tier_pr.py:961` writes only a tighter tier. Two writers would then edit one label.

4. **"Merge rules match the owner's answer to decision 2."** Could not determine the answer. The record shows the App merges proposer PRs as well as observations: PR #93 on 2026-10-28, and D1:157. The comments say a human merges (`propose-tier.yml:13-16`). Whatever the owner answers, required review stays on `main`, so a merge needs either a person or the App approving.

5. **"The caller pins the platform loop by signed tag."** As written, this does not verify anything. GitHub resolves `@tag` and checks no gitsign signature, and a tag can be moved. To carry rule 1, the caller should:
   - name the reusable workflow by its full 40-character commit, with the tag in a comment;
   - have a first job that checks the tag resolves to that commit and passes `gitsign verify-tag` offline against `^https://github\.com/policy-as-versioned-platform/platform/\.github/workflows/cut-release\.yml@refs/heads/(main|release/[0-9]+\.[0-9]+\.x)$` (`platform-tools.py:20-22`);
   - have the loop job depend on that first job (`needs:`);
   - have a Renovate regex manager move the tag and commit together, the shape of `renovate.json`'s existing {tag, commit} managers.

   Two parts are unproven:
   - No cross-organisation workflow call has ever run in this estate (L16:32).
   - A commit signed inside a called workflow may carry the called workflow's identity rather than the caller's. That would change the proposal-identity pattern (`propose-tier.yml:83`) that any check of the loop's commits copies. Could not determine without a run.

   All of this probably pushes the caller past 25 lines, to perhaps 40.

## 5. What else would break, and the order

- **Renovate goes silent** if `renovate-run.yml` leaves while `renovate.json:4` still says `enabled:false`. Keep a cut-down runner, or flip the config and accept the hosted app. The hosted app cannot run post-upgrade tasks, which is harmless once `composed/` has gone.
- **Every Renovate bump fails its artefact step** if `complete-feed-bump.sh` goes while `renovate.json:136-145` still names it.
- **The old composer's twin-agent price changes** (`composition.py:4528-4545`; the reach becomes None) if `shift-left.yml` goes while the composer still runs. This is harmless after the cut-over.
- **Flux freezes** on driftwood's own tags if `cut-release.yml` goes before the adopter's Flux source follows `main` (`gotk-sync.yaml:21` v4.0.0, `composed-set.yaml:73` v5.3.0). Switch the source first.
- **Settings outside git stay behind**: the `observation-delivery` environment and the `PAVC_OTHER_HAND_PRIVATE_KEY` secret (`observation-delivery.yml:39,75`). A person removes or keeps them. Nothing in git does.
- **Parked hub checks go red** if anyone runs them, for example `hub/verify/schedules`. They are parked with the truth surface.
- **`gitops/engine/kyverno.yaml`** names this directory's two readers. If the target keeps an engine pin, the platform proof workflow or the laptop harness must read it instead.

Order:
1. A person reads the branch rules.
2. A PR switches the Flux source to `main` and stops the five old clocks.
3. A PR removes shift-left, `composed/` and the Renovate post-upgrade task, and adds the caller and the cut-down runner.
4. The reset PR resets the rung and moves the pins.
5. Park the rest.

## 6. Recommendation: shrink

Keep, as named parts:
- **A new `workflows/loop.yml` caller**, 25 to 40 lines: a schedule, a commit-pinned `uses:`, a tag check job and the permissions the loop needs.
- **`workflows/renovate-run.yml` cut down to about 40 lines**: checkout, Node 24, `RENOVATE_FORCE`, `npx renovate@<exact>`. Drop the gitsign install, `allowedCommands` and the lane-cage step once no post-upgrade task exists.

Park everything else (about 6,650 lines): propose-tier, shift-left and the adopter gate, drift-sample and observation delivery, twin-sweep, the adopter release workflows, the compiler-pin plumbing, rulesets and tests. Park them only after the target loop has recorded its first ledger line from a probe. Before that, they are the only running loop steps.

Before parking, copy rules 1 to 16 into the platform loop and proof workflows, `probe.py` and the caller.
