## Attempt 2: show the loop breaks or loses something without it

- `platform/.github/workflows/cloud-release.yml:37` runs `engine/install-kyverno-engines.sh`.

### Lessons that live only here

Each is a rule, not code. The minimal loop needs the rule, usually in a few lines.

1. **A partial sum gives no verdict.** Commit a6636b9: a 10,000 tiered line plus a 50,000,000 untiered line against a 40,000 band gave 7,000 and "within". The code is now `composition.py:5240-5252`. The target's `within-partial` rule already covers this. It must be in `test_loop.py`.
2. **A tolerance in another currency is converted, or there is no verdict.** Commit b216e4d; code at `composition.py:5253-5262`. The target names no currency rule. Today all figures are GBP, but `ico` turnover and any foreign fine need the same rule.
3. **The `party.yaml` reader must refuse:**
   - duplicate keys (`party_artefact.py:647-668`, `_PartyLoader`);
   - a half-declared size, because absent is not zero (`:336-365`);
   - a YAML boolean read as an integer, because `True == 1` in Python (`:378-381`);
   - a declared pin version that disagrees with the pinned tag (`:525-569`).
   Commit eacc615 adds: read the captured bytes once, and price from that one declaration.
4. **CI checkout fetches no tags, and its second fetch flattens an annotated tag onto its commit.** Commit cf65df2 found that a correctly signed pin was booked as a six-figure "untagged" hole. Those shapes now read as could-not-look. `platform/.github/workflows/release.yml:94-98` re-fetches the tag for the same reason. The target's `loop.yml` verifies feed tags, so it needs `fetch-depth: 0` and `fetch-tags`, or a re-fetch of the tag ref. A missing tag must read as could-not-look, never as unsigned. The recovered note `backup/.scratch/ecosystem/research/resume-2026-10-04/adopter-source-A-shallow-CI-layout-diagnosis.md` records the same defect in driftwood and ludlow.
5. **PriorityClasses travel with the cage that names them.** `composition.py:1160-1162`, ticket 111: "every adopter's composed tree dropped it while the cage beside it went on naming it, and the Priority admission plugin refused every pod the cage mutated." The target describes cage 8 as "two Kyverno bodies" and does not mention the four classes that `cage-tier` names. The cage tag must ship them.
6. **Never write `validationActions` on a MutatingPolicy or GeneratingPolicy.** The Kyverno schema refuses it (`composition.py:1491-1496`, ADR-0016).
7. **Substrate Namespaces must never be governed.** `engine/namespaces.yaml:5-26` and commit 3d7f098 (ticket 113): label `kube-system` or `flux-system` governed and "the cluster stops". CoreDNS survives because its pods claim no policy version. The cage 8 bodies and the laptop harness must keep that condition.
8. **The UPDATE operation holds labels only. The cage body fires on CREATE.** Commit de95c11 (ticket 89): an UPDATE arm that reapplied the body to a running pod tried to append a container and rewrite priority, and the API server refused it. This lesson lives in the cage bodies more than in L13, but it is recorded in this component's history. Cage 8 must keep the split.
9. **Kyverno version facts.**
   - `engine/kyverno/engine-table.yaml:44-56`: the frozen 5.0.0 `cage-tier` body does not compile on 1.19.1, and "nothing here is typed from memory".
   - The table is the only place in the chain that holds the darwin_arm64 CLI checksum (`cc69bc66…`). The laptop harness needs it, or must take it from the Kyverno release's `checksums.txt`.
   - The consumer test must pin a CLI and check that `kyverno version` reports it before running. `ci-check.py:28-30` and `install-kyverno-engines.sh:33-34` both enforce this.
10. **A served policy self-scopes on its version label, so an offline test must stamp that label.** `ci-check.py:9-14`. `kyverno apply` reports the CEL verdict whatever the Audit/Deny action (`:16-22`). This matters to the cage 8 consumer test.
11. **Proposals: no merge path, and rejections keyed per organisation and derived, never from a shared fixture.** `honesty/proposer_bounds.py:14-28`: the old committed `rejections.json` "every adopter read ... as its own and would have been suppressed by a rejection it never made". The target's rule, "a closed one is a veto until an input changes", must be derived from that adopter's own closed pull requests. The loop must expose no merge.
12. **The one closed feedback loop today is the "fix" lever.** `composition.py:3847-3862`, ticket 121 (commit 5dadf00): marking a regulator's control as implemented takes its weight off the fine line. Its own selfcheck moves 1,787,177.08 to 1,251,023.95. The target names "fix a control" as a lever outside the cage and takes none. `LOOP.md` does not exist yet, so "recorded in LOOP.md as parked" is a condition to meet, not a fact. The weights are editorial in the regulator's feed (map A4 (b)).
13. **If insurance ever returns as a lever, use the partition.** `tcor/tcor.py:21-33`, ticket 79 item 8: premium = (1 + load) × E[max(L − D, 0)], residual = E[min(L, D)]. The old formula charged the deductible twice.
14. **Small ones:**
    - `honesty/reflexive.py`, commit c4463fa: check the public signing key, not the private one, which is never committed.
    - Commit 8c7f6ee: a hash comparison through `$( )` strips trailing newlines, so the comparison could never pass.

## Which attempt succeeded

Attempt 1 succeeded against the target's description and its lift sources. Attempt 2 found no code on the target chain that needs this component. It found four workflows and the hub truth run that break when these paths leave main, and fourteen lessons the minimal loop must carry.

## Recommendation: park

- **Not keep.** Nothing here runs in the target. Its pricing, comparison and gates are replaced by `loop.py` and the probe. `tier_binding.py` is the opposite of the target rule: the target corrects a hand-loosened rung on the next cycle instead of blocking it.
- **Not shrink.** Each candidate small part is already duplicated where the target needs it:
  - the engine pin is in driftwood's `gitops/engine/kyverno.yaml` and in `release.yml:52-53`;
  - the party checks are about 20 lines to restate in `loop.py`.
  The darwin checksum can be copied from Kyverno's own `checksums.txt`.
- **Not cut.** Adopters pin `v6.3.0` (an annotated tag, commit d0d0ace). The lessons above are cited to these files and commits. Today's chain runs on this code until cut-over.
- **Order of the park:**
  1. The new loop has seven consecutive daily cluster lines and `proof.yml` is green.
  2. Park the hub truth workflow, or at least `truth.yml:374`'s engine-table read.
  3. In one platform change, remove `release.yml:83-87`, replace `cut-release.yml` and drop `cloud-release.yml` and `recovery-expense.yml`.
  4. Retire driftwood's `shift-left.yml` and `propose-tier.yml` before any tools-pin bump.
  5. Park `compose/`, `computed-semver/` and `engine/` together.
  6. Keep tag `v6.3.0` and do not delete tags.
