## What the minimal loop must absorb

1. **An authorisation index.** In the hub, beside the owner's dated words, write a dated authorisation index: one line per relayed approval, giving the date, the owner's exact words, the action, the approved head, and `path@fc37a668`. It is small, and it keeps the record of who authorised the releases now served without keeping 1.3M lines.
2. **Rule from the `0001` patch: rewriting the rung changes one line only.** Write the rung with an exact, line-anchored edit. Add a test that the rewrite's diff touches exactly that line, so a yq-style tool cannot take comments or neighbours with it.
3. **Rule from ticket 60: the harness waits in an asserted order.** The admission webhook must be ready before any workload is applied, and the test reads the steps back to prove it. A pass that only came from a timeout counts as not looked. Download into a temporary directory, never the checkout. Today this lives in driftwood `drift-sample.yml:135-302` (round 4). Carry it into the target's proof workflow and laptop harness. This matters for "the probe reads the rung on every pod": pods admitted before the policy is ready are never re-caged.
4. **Pinned links.** If ADR-0033 survives, rewrite its link at :151 to a commit-pinned URL. Do the same for any kept ticket.
