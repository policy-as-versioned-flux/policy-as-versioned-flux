## 2. Attempt two: show the loop breaks or loses something. PARTLY SUCCEEDED. Nothing breaks. Knowledge is lost.

I read the git history (`git log -- docs/adr`: 112 commits) and the ADRs the target's rules touch. The directory holds measured facts, and the new design repeats several of them without citing them. If the directory were ignored, the new probe and ledger would likely re-learn them with live bugs. The lessons that live only here:

1. **ADR-0028, point 3 (the bracketed control).** The new probe brackets every network probe with a reference pod, before and after. ADR-0028:56-90 is where that was learned. A pod that reaches nothing because the cluster is broken must not read as a cage that held. The first cut read the control ten times and the caged pod once, so any outage that cleared between the third and twelfth exec scored as a cage that held (review F-02, corrected 2026-09-10 before merge). The silence must also persist across several reads. The stated residual is that an outage wholly between two working control reads is still unobservable. The new "reference that worked" rule must keep the before, after and persist legs, or it repeats F-02.
2. **ADR-0028, point 3b (the cage must have acted).** Review F-03, measured live: with `cage-tier` installed and Ready but its version match neutered, fact 6 returned TRUE ("admitted and Running on priority class none"). An installed policy whose webhook is not yet configured admits workloads unmutated, and looks to a name match exactly like a cage. The cage in force is picked by the policy's own readiness, and "no tier stamped" means could-not-look. This is the evidence for the target's "label alone lowers nothing" and "a cage that failed to arrive leaves the figure up". The new probe needs the check that the rung label and the stamp are on the running pod, plus webhook readiness.
3. **ADR-0028, context facts 1 to 3.** At composed policy 3.0.0 (what every adopter lane reconciled) the cage was a refusal: the API server declined every pod (`no PriorityClass with name cage-baseline-3-0-0 was found`, then `the integer value of priority (0) must not be provided in pod spec`). The cage in force on every adopter was graded by nothing. For cage v8's consumer test and for `serving-lost`: serving has to be measured on the running pods, and a bundle missing its PriorityClasses is a refusal that looks like a cage.
4. **ADR-0022 and its 2026-09-02 note (owner's own reason, the only owner-reasoned cage rule).** No Deny: a workload may find itself unable to run only because it does not fit the cage, never because it is deliberately denied; the estate is a mutating admission controller more than a validating one. A `replicas: 0` bottom rung was considered and rejected as "a refusal under another name" (ADR-0022:85-92). `infra` is a role, not a rung (ADR-0022:237-241, ticket 113). This is the source of the target's "Never a deny" and of `may_stop_serving`. ADR-0039 should quote it.
5. **ADR-0018 and reversal 13.** The tier is written on the Namespace manifest, not on the pod, because the pod label is forgeable (ADR-0022:85-86 rejects the pod label). The target already follows this, but the reason must travel.
6. **ADR-0020 (instrument against behaviour).** A missing behaviour is priced (stale size facts widen to the statutory cap, an untagged pin is priced). A missing instrument (no price for a declared regime, no FX rate) refuses the number, because "it invents a number with no source". This is the same rule as the target's ONE RULE ON NUMBERS and NO MEASUREMENT, NO MOVE. The exact parallel: an uncounted penalty rate is 1, a missing number is a lower bound, an unreadable probe is could-not-look. The hard-won detail: the live bug was summing unconverted currencies (GAPS 3.18). ico and feeds are single-currency in the target, so that lesson only matters if FX returns.
7. **ADR-0035 (CVE priced from the adopter's own scan).** An image not pinned by digest is an instrument fault (driftwood's `checkout-svc` runs on bare `nginx`, `gitops/apps/pod.yaml:51`). trivy is pinned to a release by checksum with `--timeout`. The KEV feed fit in one NVD page (1,725 of 2,000). A PR opens only when the id set changes; a new scanner or database date alone opens none. The trivy-operator was dropped (its KinD quirks are in memory `feedback_trivy_operator_kind_quirks.md`). A scanned CVE the feed lacks is a named absence with no amount. That is the new inventory.py and the daily exploited-flaw fetch. A 2026-09-25 measurement found 287 vulnerability ids in the served images and none in the old illustrative feed. The new design must say the same thing in its own terms: an unlisted flaw is a named absence, never a guess.
8. **ADR-0006 (deterministic policy).** Rendered policy bodies are byte-identical across every date. The price may move with the date, the verdict may not. This is what lets "a label alone lowers nothing" be testable, and it is why a rung change is a reviewed commit and not a timer.
9. **ADR-0024 points 1 and 2, with ADR-0023.** A clock may append observations and propose; only a reviewed change enacts; an observation never changes priced evidence. This is the target's "one proposal open at a time, a person merges". The October delivery amendments (ADR-0024:430-533, ADR-0037) are plumbing for the truth surface and do not need to travel.
10. **ADR-0015 against ADR-0022 (the ratchet contradiction).** ADR-0015:50 and :68 say "proposals go both ways" and reject a tighten-only proposer because it "ratchets the estate toward deny and never recovers". ADR-0022:110-168 (note of 2026-09-04) later made the proposer tighten-only without bannering 0015. The estate then sat at the top rung with no way back, which is what the rejected option predicted (maps/A4:246). The target's "loosening only by release, one notch, a person merges" reverses ADR-0022's tighten-only and sides with ADR-0015 point 7. ADR-0039 must say this out loud, because the record currently says the opposite on the most-cited point.
11. **ADR-0026 (a hole is priced, never refused; "selection ratchet rejected as a wall in slow motion", ADR-0026:187).** The target ratchets one notch per cycle with a stop condition and loosening path. That is a different thing from the rejected selection ratchet (a one-way lookup with no exit), but a reader meeting the word in 0026 will think the target contradicts it. ADR-0039 should say why it does not.

What no ADR says and the target adds: the compare step, the stop condition and the loosening rule. H12's contradictions 2 and 14 record that nothing in the ADRs, glossary or NORTH-STAR defines "until exposure is within tolerance". So ADR-0039 is not a summary. It is the first record of the owner's loop.
