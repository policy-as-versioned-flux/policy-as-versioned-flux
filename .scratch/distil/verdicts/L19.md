## Attempt 2 - it breaks or loses something without it: PARTLY SUCCEEDS, only if cut early

Things that break, all of them on the old chain and all in the same cut-over:

- If `composed/` is deleted while compose-check stays, `shift-left.yml:498-502` ("the regenerated composed artefact differs from the committed copy") fails every pull request, and `render_composed.py reach`, `test_composed_reach.py`, `drift-sample.yml` and `adopter-gate.py` fail. So the deletion must be in the change that removes compose-check, as the question says.
- If `selection-policy/` is deleted while `party.yaml` still publishes forward-intel, the composer refuses. Same ordering.
- `gitops/composed/composed-set.yaml` is OPT-IN (its own header says it is not in `gitops/apps/kustomization.yaml`; only `drift-sample.yml` applies it, on an ephemeral KinD cluster). So no persistent cluster loses its cage. Removing it from main loses only the daily throwaway proof.
- Hub truth-surface scripts and tests name driftwood tags and artefacts (`hub/verify/cited-truth`, `hub/tests/test_*`); the truth surface is parked, so they go red or are parked with it. I did not run them.

Lessons that live only here (what is lost if nobody carries them):

- `selection_policy.py:select` comment: the band is `<=`, "a band is a limit you may reach", chosen because two implementations disagreed at the boundary. The target text already says "at or below tolerance", so only the test case needs to survive: a residual exactly at tolerance is `within`.
- Refusal of mixed currencies (residual in one currency, tolerance in another) rather than guessing. The target has no FX step; it must either state GBP only or refuse the same way.
- Refusal of a tier name not on the ladder ("a loosening nobody signed"). The target's loop must refuse a rung it cannot rank, and must rank any declared rung including one above the pricing ladder (the 1.1.0 fix of 2026-09-04, commit 8803d72: refusing a legitimate `infra` declaration was a real bug).
- Tighten-only against what the Namespace declares today, and "held when it would not tighten". Target: "never loosens by itself"; loosening only by release PR.
- Veto key. README says a rejected proposal's ledger is keyed on policy version plus curve hash, so "a tier a human closed stays closed only while the curve behind it stands". Target: "a closed one is a veto until an input changes". The target must define "input" as a stable hash over the priced inputs (rows, probe closures, tolerance, cage version). `curve_hash` (canonical JSON, sorted keys) is the technique.
- The refusal that `selection_policy.py` and `graded/cage.py` must agree (verify/pound-seam). With one implementation this guard is gone, which is a gain, but the boundary test should move into loop.py's tests.
- From `composed/evidence.json` price lines: the honest labels `lef_basis` ("editorial midpoint, COULD NOT LOOK: no run of this estate has counted events"), the CVE line that prices nothing (418 scanned CVEs, intersection with KEV 0, `absence_only: true`), and the ICO fine line `1,787,177` that carries 98.9% of the priced subtotal. The target's feeds rows must carry a `basis` per number so `sourced_share` and `weakest basis` can print. Those basis strings are the only copy of the "what would close it" wording; they should be moved into the rows (feeds repo), not left behind.
- Fail-closed to `isolated` when nothing is under tolerance (`select`, `FAIL_CLOSED`). Do NOT carry this over: the target's SATURATED state holds, goes red and prints the shortfall. It is a deliberate reversal.

## Which attempt succeeded

## What the minimal loop must absorb

1. Boundary test: at-or-below tolerance counts as `within`.
2. Refuse unrankable rungs and mixed currencies; rank an above-ladder declaration (`infra`) as tighter than any selectable rung.
3. Input fingerprint for the "closed proposal is a veto until an input changes" rule (canonical-JSON hash).
4. Move `lef_basis`/`magnitude_basis` wording and the "what would close it" text into the feed rows so `sourced_share` has something to count.
5. A delivery route for cage v8 bodies from platform to the adopter's cluster (the existing `gitops/platform` source is the working precedent); the label-only negative control must use the same route.
6. Decide what replaces the orphan guard (refuses pods claiming an unserved policy version). The target has one cage version, so it is probably unnecessary, but it is a stated decision to make, not an omission.
7. Decide what replaces `governed-namespace-guard` (Deny on ungoverned edit of the Namespace). The target says a hand-loosened rung is corrected next cycle, not blocked, which is a weaker guarantee on purpose.

## Recommendation: cut, at the cut-over, in the change that removes compose-check

- Not keep: 26k generated lines, none read by the target, and the daily Renovate/war-gamer commits churn them.
- Not merge/shrink: the useful part of `selection-policy/` is about 30 lines of rule and test that belong in platform `loop.py` and its tests, not a place of its own. `composed/` has no small part worth keeping; the vendored feeds and converters are copies of ico and feeds, which stay as publishers.
- Not park in the working tree: a parked `composed/` keeps shift-left's regenerate-and-diff gate and the composer's refusal alive, which is exactly the chain being replaced.
- Keep the last signed tag (v5.3.0) as the archive. Do not delete tags. Consider freezing `gitops/composed/composed-set.yaml` as removed only after the target cage route is proven, since that file is the only opt-in installer of the current cage and nothing else would install v5-v7 bodies.
- Confidence medium-high. Residual doubt: I did not run anything; whether any cluster outside the repo follows driftwood `main` (not a tag) for `./composed` I could not determine, but `composed-set.yaml` pins a tag.
