## What the minimal loop must absorb

These are rules, not files.

1. **The loop never merges its own change.** It only opens a pull request, and a person merges. Absorb into `platform/LOOP.md` or the reusable workflow as a testable line: the workflow token has no merge permission, and a test reads the workflow back to prove it. This is the one enforceable lesson from ticket 66 and 142. Read the file back; do not trust the sentence.
2. **A guard is only real if a test reads its registration back, and the shipped default must be asserted.** The 2026-08-29 failure was a permissive default that looked like a working guard. The new loop's equivalents are the label-only negative control and the "cage failed to arrive leaves the figure up" check.
3. **No model on the clock.** The target has none, which agrees with the skills' stance. Say it once in LOOP.md. The derived-probability rule that an assertion may not lower a figure matches ONE RULE ON NUMBERS: an unsourced number may raise, only a measured closure may lower.
4. **If the spine ever wants a human-run reasoning step**, the pattern to re-home is: output is one reviewed PR, a validator refuses a stub that passes anything, and a headless run writes no override. This is optional. No skill is wanted by the loop today.
5. **Permissions allow list.** It stays with the owner, in the hub.
