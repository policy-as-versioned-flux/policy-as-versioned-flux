# Existing-CI tiny Linux lease control — source contract

This is a TEST_ONLY source implementation. It supplies no Qwen asset/runtime,
model measurement, qualified Actor, population, registration or permission.
Actual installation, privileged execution and ordinary CI publication require
separate review and authority. A portable test passing on macOS is not a Linux
kernel observation.

The existing twin workflow's two Ubuntu24.04 determinism rows have one literal
bootstrap and one always-upload step. No job, runner, provider, account, service,
schedule or dispatch is added. The Mac row and existing proof steps keep their
order. The root payload executes existing `/usr/bin/python3.12 -B -I -S` with a
clean environment. Its literal reviewed manifest digest pins nine fixed source
members; checkout bytes are read as bounded DATA through no-follow directory
fds. No checkout Python/shell is executed as root. The fixed STORE must not exist;
unsafe or stale state is refused, never overwritten, chowned or recursively
removed. The OS interpreter, env and dash are observed protected image TCB, not
claimed to be a previously acquired Qwen runtime.

One original monotonic 900-second budget starts before source read/copy/discovery.
The protected root startup receipt binds the same process PID/start and exact
reviewed source manifest. The fixed ci entry cannot select a command, path, UID,
cap or clock. It retains that clock across discovery, all six scenarios/twenty
serialized subcases, scoped cleanup, root streaming, nonroot artifact unpacking
and final local disposition. Attempts remain60 seconds, the negative deadline
case30, and teardown10 inside those ceilings. The workflow's17-minute emergency
limit is not a renewed lease or cleanup proof. Artifact upload has a separate
finite5-minute transport timeout after local completion.

Only this new ci-suite source constructor can choose literal `/sys/fs/cgroup`.
The original one-scenario constructor keeps its original fixed child parent;
production validators still reject TEST_ONLY descriptors. Root explicitly accepts
one unmanaged direct-root-cgroup leaf as a laboratory exception in each fresh
disposable existing CI VM. This is not systemd delegation or a production
arrangement. Actual cgroup-v2 mount, same guest cgroup namespace, protected systemd
PID1, already-enabled memory/cpu/cpuset/pids and two eligible CPUs must be observed.
No root/ancestor cgroup.procs/threads/subtree_control/limit, controller, manager,
unit or service writes occur. No enablement or infrastructure fallback is supplied.

At most one owned leaf is ACTIVE. Each of twenty subcases uses the existing fresh
random lease/Leaf; paired preflight/generate share that leaf. The previous exact
mount/device/inode/pidfd-scoped removal must be verified before the next starts.
A stale lock, changed identity, failed cleanup or lost proof aborts the suite;
there is no leaf/inode reuse, concurrent leaf, sweep or process-group cleanup.
The existing kernel mechanics, detached descendants, unrelated sentinels and
supervisor/guardian loss witnesses are reused unchanged.

Discovery pins actual loaded OS stdlib/cache/native bytes, their identities and
ELF PT_INTERP/DT_NEEDED closure from current mappings. No ldd, package discovery,
installation or model import occurs. Ambiguous/missing dependencies, mutable or
foreign toolcache sources, aliases or more than256MiB/4096 files refuse admission.
Existing fixed distinct unused irc39/39,14GiB initial headroom, recurring2GiB outside the
12GiB leaf and5GiB backing storage remain genuine prerequisites, enforced again
by the existing leaf/phase/sample mechanisms. No existing target is presumed to
satisfy them.

Initial unavailable native prerequisites yield explicit SKIP/zero control credit.
Unsafe bootstrap/store/source/issuer failure is a failed invocation; every started
subcase failure is FAIL/UNVERIFIED. Root originals are retained, including failed
attempt journals. No skipped/missing receipt passes. The suite verifier reuses
the actual existing per-scenario verifier and requires all six/twenty in order,
each original sentinel/terminal/removal witness and one unreset timeline.

Root exports only fixed source/installation/start/host/results, twenty known
case journals/records and their specifically referenced protected receipt files.
No recursive/private/workspace collection or credential/runtime bytes are sent.
Limits are16MiB/file,128MiB original bytes,256MiB framed wire bytes,4096 members,
64KiB/frame; excess is a retained failure, never truncation. The nonroot receiver
requires exact chunks, complete manifest, actual result/header agreement and, for
PASS, every source/start/host/installation/case journal/record and referenced
receipt. Exported Python remains DATA; the reviewed local reader validates records.
This parser never imports an artifact as a protected catalogue or issuer.

`native-disposition.json` combines the root process exit and receiver exit with
the original receipt. A transport/process failure cannot retain a final successful
disposition or become SKIP. `native-outcome.json` and `suite/result.json` preserve
the original decoded root evidence. Missing bootstrap/stream/teardown/artifact is
unverified; job green, VM disposal and timeout are not kernel PASS. All successful
tiny-control records still state `production_capture_accepted=false`.

Remaining real prerequisites include independently reviewed exact bootstrap/source,
actual disposable-VM observation/closure/capacity, actual control execution and
complete terminal/export/artifact evidence. Actual Qwen runtime/assets/acquisition,
model output review, qualification and natural programme outcomes remain separate.

## Revision01 safety corrections

Checkout DATA is opened nonblocking and admitted as a bounded regular file
before any read. Each read checks the original deadline. A one-shot default
SIGALRM timer is armed for the remaining original budget before filesystem setup
and retained across exec; it is never renewed. Timer expiry is failed/missing
evidence, never a cleanup witness. Scheduling latency and actual target timer
behavior remain unmeasured. The17-minute workflow limit grants no extra budget.

The literal bootstrap rereads its protected installed manifest and every one of
the nine source/entry copies, verifies exact original bytes and hashes, and only
then executes the first fixed entry. Later coordinator self-checks remain an
additional check. Unsafe source/ownership/ACL/closure/issuer errors propagate as
failures; only explicitly typed, observed missing native capabilities/capacity can
produce initial SKIP. Unknown and malformed readings cannot appoint that status.

Caller, principal, kernel, installation and host observations are written and
fsynced as immutable protected originals under fixed STORE/ci-evidence names as
each becomes available, before subsequent phases. Export reads those same bytes
back under their original hashes; export failure does not erase the originals.
The source-bound workflow run/attempt/source/job/repository/architecture context
is recorded alongside separately observed protected OS-release bytes, kernel and
Python identity. Workflow labels are attribution, not independent native
proof. The runner image build identity is explicitly unknown. No runner or
workspace environment is imported into the helper/child.

After persisting every returned attempt, the CI coordinator invokes the existing
per-attempt terminal/sentinel/removal reader through its public verify_attempt
interface before permitting the next subcase. Intentional missing terminals in
the specified guardian-loss/observer controls retain their existing meaning.
Unexpected missing proof aborts immediately; the legacy single-scenario route
and all resource bars, profiles and numerical/scenario grading remain unchanged.

## Revision02 availability and failed-admission originals

Only the initial presence check of literal `/sys/fs/cgroup` converts its actual
FileNotFoundError into typed availability. The CI-only literal `irc` lookup
similarly converts only its own missing-account KeyError. Original error type,
arguments and fixed lookup/path facts are retained in the protected availability
record. Legacy lookup behavior is unchanged. Unsafe ACL/ownership, shared/active/
malformed identity and later source/integrity errors remain failures.

A capacity admission refusal after initial setup remains FAIL. Before returning,
the coordinator persists its current raw readings, actual phase/scenario and
original deadline as an immutable protected failed-admission record. The outcome
references those exact bytes/hash; export reopens that fixed record under its
original pin, and the receiver refuses missing or changed referenced evidence.
Neither an earlier successful host record nor an exception string substitutes
for the current failed readings. There is no reset, retry, fallback or new lease.

## Refused caller ancestry diagnostics

A mixed-credential launcher ancestry remains refused. The fixed source retains at
most 32 observed ancestor PID/start/PPID/UID/executable rows with an exact omitted
prefix count; executable prefixes are capped at 4096 characters and explicitly
marked when truncated. These are pin/readlink-time observations, not a successful
final chain verification or a new sudo/environment authorization route. The CI
suite persists and hash-rereads the refused ancestry through its existing protected
caller record, then exports `FAIL` / `executed: false` under the original 900-second budget
before principal/kernel/leaf setup. A failed protected write/readback or changed
record cannot become a complete export. No actual CI UID tuple or valid privilege
transition is inferred from the original ambiguous-ancestry traceback alone.

## Source-appointed CI sudo caller route

The fixed CI suite uses `ci_original_caller(g, deadline, *, pid, start)` only after
installation/source verification and admission of the protected original startup
receipt. `pid` and `start` are comparison bindings for actual self, never process
selectors. Neither environment/SUDO_UID, CLI/JSON, a supplied record, a workflow
label nor a public approval flag chooses this route or a caller. The existing
single-scenario `original_caller`, `_protected_launcher`, guardian `Identity` and
all production/closure protected-path predicates remain unchanged.

Root's explicit disposable-CI policy admits only `S(u) -> R(u)` or
`S(u) -> S(u) -> R(u)`, from actual self's observed PPID. Each S is the exact
protected `/usr/bin/sudo` image with `[u,0,0,0]`, nonzero same kernel-observed u,
setuid-only privilege mask, single-link regular root-owned immutable path and no
ACL/capability. The immediate first non-S must have `[u,u,u,u]` and a protected
nonprivileged executable. No intermediary is skipped. The two-S policy includes
matching same-user nested sudo. It authenticates neither monitor/PTY roles nor
installed sudo version. No fourth ancestor, process action, signal or enumeration
is used. The endpoint's parent is observed but not traversed.

Self plus at most three ancestors are pinned using the unchanged Identity.
Root clarification01 corrects the document schedule to pin before the new raw
snapshot, so pidfd liveness actually brackets the bounded status/stat/exe reads.
First-image-last acquisition and reverse old-image-close-first verification
preserve peak12 **including** inherited temporary readers. Both passes compare
PID/start/PPID/all UIDs and actual executable O_PATH fstat against the independently
protected named file, then repeat final all-held liveness. Equal endpoints are
not an atomic/continuous snapshot or proof against trusted-host interference.

One-S success has48 opens/47 closes/one live transferred endpoint, peak9; two-S
has64 opens/63 closes/one transfer, peak12. Cumulative64 is distinct from live12.
Opaque inherited failures retain bounded count intervals and possible ownership;
ambiguous closes are never blindly retried. No new evidence descriptor is opened
without headroom. The coordinator's writer/readback/verify use four later
serialized opens (68 combined for two-S), outside the frozen acquisition record;
later export/release are separate phases. No second budget or timer is created.

Closed bounded passive records retain both passes' actual raw bytes and binding
facts (status65536/stat8192/exe4096, at most eight snapshots, one MiB record).
Refusal remains FAIL/executedfalse before principal/kernel/closure/leaf work.
Exclusive protected persistence, immediate hash/readback and endpoint verify
precede those unchanged gates; final export rereads the same original bytes.
Incomplete persistence, expired time or unknown custody cannot issue permission.
The pure structural checker never imports a record as a live caller capability.

The four retained diagnostic CI observations established only the first sudo
UID shape `[1001,0,0,0]`. Full parent chains, file bindings, genuine pidfd/descriptor
custody, original-budget compatibility and all twenty actual subcases remain
unproved by this source implementation and its pure models. Independent review,
fresh-main replay and exact new execution/publication GO are still required.

The CI-only principal is source-fixed to the already existing `irc` account,
UID39/GID39. This is a prospective selection, not proof that a runner supplies a
suitable account. UID/GID aliases, shared primary or supplementary membership,
active tasks, caller collisions and exposed homes still refuse. There is no
account creation, mutation, fallback or public selector. Ordinary production
retains its existing `nobody` policy; a neutral initial lookup absence cannot
count as an executed control pass. Both warmup and every actual attempt
reacquire and validate the same fixed CI identity.
