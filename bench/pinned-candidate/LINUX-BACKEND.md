# Paired Linux candidate source

This source implements a fixed Qwen child and a protected, foreground Linux lease.
No Linux model execution, installed authority, acquisition, resource feasibility or
qualification is established by these files. The empty operational registry refuses
both invocation and operational actor freezing. The original Mac smoke, runtime,
limits and evidence remain historical and unchanged.

## Callers and actor identity

`twin.linux_candidate.invoke_pair(request, config)` owns both fresh subprocess phases.
The exact candidate request is `{input, prompt_utf8}`; input can be the signal JSON
object or generator YAML text. Neither expected answers nor reference bases are sent.
The signal adapter routes its operational profile here. The generator consumer uses
the same case-free interface when integrated. Unprotected signal transport requires
an explicit `purpose: TEST_ONLY`, and never supplies Linux authority.

Two separately named, unmeasured profiles are supported:

| Profile | Full input cap | Generated cap | Context cap | Raw cap | Whole attempt |
| --- | ---: | ---: | ---: | ---: | ---: |
| `signal-linux-bf16-v1` | 4096 | 512 | actual pinned model capacity | 131072 bytes | 900 s |
| `substrate-linux-bf16-v1` | 4096 | 2048 | 8192 | 131072 bytes | 600 s |

Both require two CPU threads, one interop thread, direct CPU BF16, eager attention,
seed zero, greedy one-beam/one-sequence decoding, dynamic cache, explicit EOS/pad
IDs and the original pinned model manifest. Bounds cannot be widened, aliased,
truncated or repaired. The larger generator context must also fit the actual model's
position capacity. Model/runtime manifests, complete configuration and all transitive
support source bytes bind the actor. Operational freezing also binds the current
protected catalogue, anchor and installed guardian closure, so future authority
cannot attach to an old actor identity.

## Protected host boundary

The judge catalogue independently pins the SHA256 of the fixed root-owned anchor
`/run/policy-as-versioned-flux-candidate/host.json`. Config or model output cannot
appoint another authority or root command. The parent launches only the independently
pinned fixed administrative entry with `--lease`; no shell payload or arbitrary
privileged command is accepted. Existing administrative rights may be broader than
this data API. This source neither installs a launcher nor changes sudoers.

The anchor records the existing supervisor/candidate identities, protected already
enabled cgroup parent, two available CPUs, fixed entry/interpreter/support closure,
and exact full-config profile allowlist. Root-owned immutable acquired snapshots
supply each regular-file readonly mount. Missing principals, mutable aliases/ACLs,
privileged binaries, unknown closures or unavailable controllers refuse. No account,
controller, service, provider or container is created as a fallback.

The guardian authenticates the original supervisor through actual ancestry, UID,
start identity and pidfd. A host-only monotonic deadline can only shorten its own
profile cap. Setup, both phases and observation work share that earlier budget;
ten seconds are reserved for verified cleanup. One exclusive candidate-identity
lock prevents overlapping leases and remains after unverified teardown.

Trusted bootstrap directly creates private mount/PID namespace init, waits for exact
cgroup attachment, constructs a readonly minimal root and proc, and supplies only a
128 MiB nosuid/nodev/noexec writable attempt tmpfs. It drops supplementary groups,
all credentials/capabilities and bounding capabilities, sets no-new-privileges,
rearms SIGKILL after the final credential change, checks the inherited guardian pidfd,
locks death-signal and namespace changes, then executes fixed Python with `-B -I -S`.
The child retains only three data pipes. No third-party code executes as root.

The existing socket filter is unchanged. A separate architecture-checked filter
prevents namespace/mount/control/ptrace/process-memory escapes and death-signal
reset; legacy thread clone remains possible, opaque clone3 returns ENOSYS. Actual
native/thread compatibility remains to be observed.

## Capture and teardown

The child checks actual credentials, mounts, namespace-init identity and controls,
restores post-exec nondumpability and requires an exact zero prctl readback,
then installs and observes kernel network denial before enabling rehashed runtime
paths. It verifies the complete model/runtime closure and full untruncated tokenized
input before loading weights. Generation repeats that exact input/token binding in
a fresh child. Actual parameters, buffers, build, CPU/ISA, dependency mappings and
runtime observations are compared with the frozen contract; no dtype/device fallback
or model-supplied identity is accepted.

Every generated token ID is journalled before decode. Decoded snapshots are bounded,
chunked and bound to the exact successfully decoded prefix. Decode errors cannot
relabel previous bytes with a later token count. Host observation checkpoints keep
the exact child alive until the guardian acquires independent backing-inode mappings
and sends a fixed acknowledgement. Complete output requires EOS, callback/tensor ID
agreement and actual runtime agreement.

Input/control is bounded at 1 MiB, individual output frames at 64 KiB, stdout at
8 MiB and stderr at 1 MiB. Per-lease source/mapping receipts live in the fixed protected
host store, each bounded at 64 MiB, with independently acquired immutable bytes,
counts, pins, inode/device and phase identities. This avoids duplicating large source
closures in stdout. Capture failures retain actual bounded raw prefixes, IDs, stderr,
resource facts and errors; they cannot provide a completed answer or semantic basis.

The cgroup enforces 12 GiB memory, zero swap, 128 PIDs, two effective CPUs and quota;
the guardian checks 2 GiB reserve and 5 GiB disk, actual counters/peaks/events and
observer gaps. Admission and every sample inspect all backing storage derived from
the fixed anchor parent (receipts, lock and root scaffolding) and the parent directories
of protected acquired files, including model/runtime/support/interpreter files. Each
must retain 5 GiB available; capacity is read through a verified directory descriptor,
with per-path device/inode/free-byte evidence. Cgroup/proc mounts are not used as
storage capacity, and the bounded `/attempt` tmpfs remains charged to memory.
The parent rejects omitted/substituted storage and changed observed directory identity.

Before input release, the guardian independently corroborates the pinned child's
post-exec zero readback with live sensitive proc ownership and verified nonroot
credentials in the same user namespace. The parent validates those protected guardian
facts; it does not reopen a child that may already have exited. Linux proc ownership distinguishes dumpable value one
from other values; these receipts do not claim an independent numeric prctl read of
another process. Actual Linux enforcement remains a required tiny-control observation.
Each phase is killed empty, observed dead and reaped before proceeding.
Supervisor death/control EOF/deadline also use that pinned-leaf cleanup. Guardian
loss kills locked namespace init, causing kernel termination of detached descendants.
Verified populated-zero/dead/reaped/removed evidence is required; a kill request or
timeout is never reported as successful teardown. Stuck-kernel cleanup remains an
explicit possible refusal.

separately reviewed tiny harness must exercise these same kernel functions on existing

unrelated sentinel survival and incomplete-cleanup refusal. The current production
allowlist API requires its actual acquired closure; a tiny harness must use a distinct
TEST_ONLY closure and cannot forge production asset/runtime receipts.

Linux package/native/model placement, fresh custody compatibility, per-output
independent semantic review and natural outcomes remain operational prerequisites.
