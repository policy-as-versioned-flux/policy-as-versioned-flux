# C1 private storage selection and conservation

This is a source-only, default-absent logical ledger. It does not enforce a96MiB collector cap, select a host, prove inventory fit, create an original suite, or grant native/extraction authority. C2 acquisition/observation and C3 finalization/export wiring remain held. All N rows and actual staging/build/PDF/native work remain unrun.

`pdf_capture_storage.check_storage_selection(record, archive)` checks closed canonical selection, retained-inventory and fixed-source DATA. Its result explicitly says qualification NONE/source_complete false. No checker result or context/hash/JSON constructs a private selection, original, stage, cell, allocation or permit. `_APPOINTED_STORAGE` defaults to None and has no setter/factory. A future separately reviewed trusted genesis must already hold the exact private `_Selection` at immutable `OriginalComparisonSuite._capture_storage_selection` birth. There is no such genesis here. Existing originals cannot migrate; normal post-birth assignment always refuses. Test fixtures explicitly fabricate shapes and prove no actual chronological selection.

The selected private seam `_allocate_selected_stage(original)` refuses started/default/foreign originals. It installs one cell on the same original-owned StageState/remap flow before any guard, charge or clock uncertainty. The earlier private guard and exact original/storage/source/inventory bytes are checked; initialization uses the original60s preparation window. The original clock, selection, guard, slot/custody counters and production/default route are never reappointed. Default stage allocation adds only an absent cell field and performs no added guard/read/clock.

The source-private interface is: `_noncapture(original)`, `_capture_allocation(original, held_H)`, `_reserve_retained(allocation, count)`, `_reserve_scratch(allocation, count)`, `_retain(original, permit, immutable_payload)`, `_spend_scratch(original, permit)` and `_close_capture(allocation)`. These are logical permit/ownership operations, not executors or native/stage entry points. Capture index is derived from the original next slot; no caller can choose a bucket, host principal or target. The original admission check stays active. A capture additionally requires a separate earlier exact H containing the original/storage/retained/source inventories, exact source bytes and earlier guard description; source roots and the same H binding are rechecked. Existing native schemas/profile/issuer/store grammar are unchanged.

There are52 fixed96MiB capture buckets and one2048MiB noncapture bucket, exactly7040MiB frozen reserve. Noncapture first issues8MiB for finite ledger metadata, without falsely retaining bytes. At most256 permits per bucket and32768 closed journal entries are supported; exhaustion permanently stops. Scratch/copy permits consume prospective bucket allowance without reserve-to-retained transfer or refund. A new genuinely held immutable payload transfers its length exactly once from the same original reserve to retained. Permit replay, wrong owner/kind, duplicate object ownership, stale bucket and reentry refuse. Successful total retained+reserve is conserved. A post-transfer failure retains the actual payload/partial phase and exact counters; no rollback or second commit invents reconciliation.

A separate conservative8MiB technical charge reserves helper2/remap4/futurefault2 once outside7040. Failure16MiB and1128MiB arithmetic slack are unavailable to permits. Old selected-path staging/collector charges have **not** been rewired: C2/C3 must reconcile these already selected charges, never call the old default charges a second time. Unused/failed/closed allocations are never refunded or reassigned.

Pending journal markers precede fallible transitions. An already bound cell stops the original without first invoking a revocable source guard; first exception/cancellation identity and bounded first failure remain held. Unknown target custody is neither cleared nor guessed. Source revocation after a transfer retains the owned bytes. No finalizer, deletion, receipt, export, target dispatch or successful terminal state is introduced here.

The selected source guard covers this helper and comparator/remap/native helper dispatch, with MetadataAuthority's unchanged core checks. Fixed source DATA reads are individually bounded, but **existing MetadataAuthority inventory/freeze/verify readbacks and downstream serializers are not yet prospectively charged/bounded**. C2 must solve that reached guard-read seam or remain held. The finite metadata charge is conservative logical accounting, not Python allocator/RAM/disk quota proof. All actual source/H/inventory appointments, trusted B entry, capacity/closure evidence and C2/C3 runtime enforcement are absent. No52-fit or successful96MiB-enforcement claim follows from these tests.
