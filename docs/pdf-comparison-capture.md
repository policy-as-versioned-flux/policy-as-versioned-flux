# Comparative PDF capture produces laboratory DATA

`pdf_comparison_capture` compares a pristine Xpdf invocation with the already reviewed instrumented invocation for the frozen 18 invented technical PDFs. It does not register an extraction profile, issue metadata or origin authority, or create receipts, indexes, extraction members or native handles. All actual native questions remain unrun until separately authorized genuine Linux builds, host selection, kernel compatibility and capacity exist.

`TEST_ONLY` is the data purpose. `actual`, `SIMULATED_DATA` and `NOT_STARTED` are distinct observation modes. Public replay checks consistency. It cannot reconstruct a private actual completion. Synthetic host-shaped models in tests are deliberately invented and do not establish a real H, genuine build or observed converter result.

The small external seams are pure `prepare_comparison_plan`, `check_comparison_capture` and `compare_simulated_pair`; private-context selection through `new_comparison_session` and `freeze_comparison_authority`; actual source orchestration through `capture_baseline`/`capture_patched_comparison`; and `compare_pair` over held private completions. No CLI, environment toggle, workflow, deployment selector or public dictionary adoption route enables execution.

A pair selection pins one public fixture/config/resource, the same release/toolchain/configuration recipe, the independently selected pristine and patched build associations, their binaries, allowed fixed differences and the original suite selection. The patched build identity uses the unchanged bridge schema. The pristine identity is a closed comparative selection record containing variant, archive, null patch, prepared source tree, toolchain/configuration recipe, executable and candidate inventory pins. These records describe the selected build; they cannot prove that a build occurred or approve themselves.

The caller must already possess the exact private native host context. The original suite selection must be present in that context's independently frozen evidence. Its closed record fixes the original monotonic start, 10800 seconds, 52 invocations, 182-second slots, 60-second preparation, 120-second target/finalization, shared two-second failed cleanup, 300-second post-terminal transport and 8 GiB storage cap. A caller-owned private session retains order, consumed host intervals, actual retained bytes and stop state. Each invocation needs its own independently selected H of at most 300 seconds, with exact build/config evidence byte equality. The ephemeral-host selection mechanism is not configured by this module.

The pristine collector inherits only original FD0–2, uses the fixed native argv and environment, and retains both streams, actual requested/accepted writes, dependency reads/maps, lifetime/exec/exit snapshots, causal positive-capacity EOF, typed raw wait and known custody. A later regular dependency may use FD3; it never becomes an origin channel. Aliases, replacements, sidecars, unexpected descendants, unsupported syscalls/flags/ABI and unexplained maps refuse before continuation. Normal completion requires actual exit0, both original EOFs and workspace cleanup within the original 120 seconds. Equal exit/wait/cleanup clock ticks are valid; EOF need not follow host observation of wait.

The new collector reuses narrow private native mechanics and common pure file/syscall replay. The latter is an internal checking projection, never a native store admission or exported v1/v2 observation. Its own DATA checker independently enforces two-channel topology, causal close/EOF ordering, the exact preselected candidates/input/config, run clock, raw wait, shared cleanup and retained buffer bounds. Public native profiles, issuer/store grammar and production routes remain unchanged.

An optional internal absolute preparation deadline is an additional restriction, not an enabling flag. The comparative routes fix it before workspace setup and pass it through private migration/native helpers. Candidate acquisition applies the earlier caller bound and its existing local 60-second bound, including checks after reads and before fork. Missing deadlines retain the previous default path. A later supplied deadline cannot extend the local 60 seconds. Booleans, NaN and infinities refuse. Default conservation and earlier/later/exact-boundary behavior are covered by pure controls.

The patched comparative wrapper runs the existing internal completed-pair bridge route exactly once. Before that call it checks the exact actual private store/host, source guards, original host window, deep-frozen candidate plan, independently selected build/config bytes, the pristine compatibility gate, same private suite and fixed slot. It compares the returned result with the separately held actual recorder copy. Successful results pass the existing full bridge validation; adverse results remain DATA. It never changes `NativeObservationFailure`, adopts its public result dictionary, deposits a native handle, or launches a second converter. A successful already acquired profile2 completion can also be read through its existing store-local opaque handle.

Full stdout/stderr bytes and natural typed terminal statuses are compared separately. No normalization, warning removal, substring search or changed fixture/config is allowed. Missing/incomplete facts remain null. A mismatch, failed capture, missing actual origin effect or unknown custody stops later slots. Cleanup intervention cannot stand in for the converter's natural terminal result. Failed DATA includes separately retained failure facts and bounded stream prefixes; pre-return errors preserve uncertain workspace and spend/stop the original session. Pure simulated matching records always retain the actual-suite stop condition.
