# PDF native host bridge — source capability

`pdf-text-xpdf-origin/2` uses the separate closed native observation v2 and execution dossier v3 grammars. Existing native v1, dossiers v1/v2, profiles, standard nine-key transform receipts and five-key custody indexes keep their grammar. `pdf_output_origin` remains a structural verifier, never an issuer.

Actual public execute calls native acquire and resolve. The internal migration executor owns exclusive input/config copies and fixed argv, invokes the internal Linux recorder, checks native custody before workspace removal, then finalizes native timestamps/terminal evidence. Only then does the bridge assemble the map, host envelope, receipt, dossier, disclosed member and index. A private completed pair carries the result and separately copied native record back to native; the result's pins cannot substitute that held record. The private store deposits only the complete verified result and frozen prelaunch plan. Resolve verifies and returns the held copy without invoking the final builder or a second recorder.

The original inherited FD3 is a write-only FIFO, generation zero, bound to the parent's actual pipe identity, initial/exec snapshots, exit-stop and positive-capacity parent EOF. Only original stdout/stderr/origin writes are admitted. FD3 explicit close, reads, aliases, reopening, metadata calls and mapping are refused before dispatch. The unchanged converter closes FD3 through actual terminal kernel closure. Full requested write/writev bytes and actual positive prefixes are retained and independently replayed; captured bytes must match. Unsupported errors, restarts, overflow, missing EOF, signals, nonzero waits and uncertain custody cannot produce a final reference.

Positive-capacity EOF also requires writer closure: FD3 follows the checked exit transition; stdout/stderr follow that transition or the original descriptor’s successful explicit close. Host EOF may interleave between close entry and leave, but that exact pending close must later return success. The envelope binds the matched entry/leave across those host events. The successful typed wait observation lies between the checked exit-stop and cleanup start in relative nanoseconds, inclusive of equal clock ticks, and stays within final elapsed time. EOF may occur before or after host wait observation. Every fixed profile limit has an exact integer primitive in both config and native v2 records; floats and booleans are refused before fixed-value comparison.

The original 120-second invocation starts before fork. Successful cleanup and native final timestamps stay inside it. Failure teardown shares one deadline `min(cleanup_start+2, original_deadline+2)` across every stage and descendant; rejected stops are never resumed. Failed retained captures share the original 456 MiB buffer allowance, recording truncation and observed lower bounds. Origin wire/record/event limits are 64 MiB/65536 bytes/1000000 events. Native file, path, trace and stream limits also remain enforced.

Before OS access, actual config and build identity pins must already occur in independently frozen private host-policy evidence, with byte-equal retained plan artifacts. Source/build strings, public envelopes, policies or copied indexes cannot select that association. The host policy states a trusted administrator controlled writer interval; ownership/FD/stat observations do not prove exclusion of administrator writes. The capability covers exact-invocation file dependencies under the trusted kernel/recorder/host assumption, not every input or arbitrary host compromise.

The pure bundle checker never accesses a store, issues a handle or approves an index. Explicit TEST_ONLY consistency uses null/null host policy fields only. Actual consistency requires non-null H/H plus native/host bindings. Public actual acquisition always performs its real source recorder path. Raw TEST_ONLY native v2 cannot issue profile2 references, and there is no TEST_ONLY profile2 execute/adopt API.

Migration authority freezes native, migration, origin and bridge module functions/defaults/dispatch and core guards. Callback defaults retain deep JSON and independently selected custody-index hashes only. After exact v3 bundle replay, every observation, publisher statement and publisher excerpt is checked against the structural map; descendants/aliases cannot strip it. The unchanged stock checker then receives the original manifest/archive/receipts/policy.

Source and pure invented-history tests do not establish a working Linux build, kernel route, emitted origin coverage, real closure, actual metadata custody or qualification. Native N01–N08 remain unrun. Real Linux source/binary/build association and independently selected host evidence are still required. Remapping resources are not silently staged through this profile; unknown resource staging/read relations remain held.

Complete-bundle pure tests require the explicitly supplied `TWIN_XPDF_SOURCE_ARCHIVE` file matching the fixed official source hash. Missing input is a disclosed test skip; tests never download, compile or run the converter. Their synthetic compiler/binary association proves structural cross-binding only.
