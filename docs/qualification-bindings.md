# Host-bound qualification evidence

`twin.qualification` binds a measured computation and population around the existing
`skills.evaluate`, `Stated`, seven scorers, thresholds and measured minima. A model name is
not a selector. The incumbent recorder now refuses another model version before evaluating
or appending; its default corpora and `CORPUS_KIND` retain their historical mechanism meaning.

The versioned `twin/qualification-registry.json` is initially empty. No new real model holds
permission, no provider or schedule is enabled, and no official score is added by this change.
TEST_ONLY controls prove mechanics and are refused by default operational resolution.

## One selection, one body of evidence

The host freezes an `Actor` from actual runner/parser functions, one canonical invocation
configuration, current Python/executable/platform identity and source/asset support digests.
Runner and parser receive fresh copies of that configuration. Their actual code identities
and source files are checked before and after invocation. Captured closure state is refused;
substantive settings must be supplied in the immutable config. Adapters are trusted host code:
they must declare all supporting computation/assets/build facts and verify any provider's
actual runtime against that configuration. An arbitrary provider's reported model string is
not attestation. The historical smoke adapter demonstrates asset/build verification; this
change does not install a general model provider.

Callable defaults have one JSON-safe comparison identity across freezing, verification and
durable import. It preserves scalar types, nested tuples/lists, mapping order and shared default
state; changing those defaults still changes the actor. Built-in JSON-compatible defaults are
supported. Custom objects or cyclic defaults require explicit invocation configuration.

A live runner returns `RuntimeResult(raw, observed_runtime)` using observations obtained by
trusted backend code from the actual loaded assets/build/computation. Those observations must
match `config.runtime_contract`, the same immutable contract used for invocation, before parsing
the response. A JSON identity asserted by the model cannot supply this host object. Bare-byte
runners are restricted to explicit TEST_ONLY mechanics or capture-only replay; replay always
refuses live permission. Backend-specific observation code remains part of the measured actor.

A `Population` conserves complete admission packets, held decisions, original source bytes,
grouping, exposure history and the predeclared applicability envelope. Mutating a returned
projection cannot mutate the retained packet. The envelope covers adopter, domain, capability,
frame, source and date; it is frozen into selection identity before any capture. Duplicate IDs
or identical task inputs cannot inflate its count. There is no results-based filter in capture.

A `Selection` binds those objects, the original metric scorer, scorer-shaped reference
projection, actual basis checker and any separate population review. Only input reaches the
actor. Every selected attempt remains in the ordered capture, including runtime and parser
failures. Actual raw bytes survive parser failure; a failed invocation that returned no bytes
says so. Invalid outputs count as wrong, without replacing the original scorer's decisions
for valid answers. Wrong, wrong-basis and unscoreable outcomes retain existing semantics.

Reference projections must themselves score correctly before baseline derivation. Baseline
answers come from those references; variance and head readings come from the exact actual
candidate capture. They share no incumbent prediction shortcut. The facts cache includes
selection and capture identities, and current source/runtime checks still run on a cache hit.

The existing frozen-field baseline is unchanged. A reference layout it cannot measure fails
closed rather than understating its bar. A baseline tie, constant field or insufficient
population remains a refusal even when the actor returns every supplied answer correctly.

## Approved substrate plant coherence

On 2026-10-30 the owner answered “Approve stronger plant checks” to the reviewed contract
exception (proposal manifest `6396010e123ec7e826998cefc9d5a173aeb62f0d1b9b834fe0faedcfeaa0a2fd`;
independent review manifest `d0dd24f08d236aaf20a1a8ae8b268f5d45caa7ffd3a2f4cee9a393dadbdfcdd7`).
This strengthens the substrate scorer while retaining all its previous checks. Channels must
contain nonempty lists of string lines, and plants must be a list of records naming a required
channel, a genuine integer nonnegative in-range index and a string signal. Each record points
to exact plant text at its own location. A line may be the literal signal or have one nonempty
`[prefix] ` decoration, without brackets or line breaks inside the prefix. Prefix identity is
ungraded. Actual occurrence counts for each declared signal must equal the metadata
multiplicities; repeated signal entries pass when each has a distinct occurrence. A line
matching multiple distinct declared signals refuses.

The claim covers structural recipe conformance and actual occurrence witnesses. It supplies
no general prose-quality, realism, focus-identity or undeclared-signal judgement. Reference
projection constructs those constraint witnesses from the labels alone, with distinct
locations and enough mundane lines for the declared floor. It never repairs candidate output
or supplies a missing candidate basis. A fresh decoration and filler avoid incidental credits
when labels themselves contain prefix syntax or the ordinary filler text.

Threshold 0.80, measured minimum 16, all ten permission conditions, the frozen-field baseline
algorithm, variance checks and the other six metric scorers are unchanged. Sixteen TEST_ONLY
dense controls demonstrate a baseline of 0.0625; the original three fixtures still give 1.0.
Neither result certifies a real population, actor, model quality or universal corpus feasibility.
No new official score or permission follows from the approval or these software controls.

Selections bind current scorer and projection source hashes. This change makes selections
bound to the old source stale; historical captures, scores and their source identities remain
unchanged. A host must freeze and evaluate a selection under the new source before making a
current claim. The existing development-only admission, custody, runtime, host-context and
default TEST_ONLY refusal rules still apply.

## Reference admission is separate from qualification custody

Current `reference_cases.admit_reference` admits development references only. A separate
`PopulationReview` must explicitly reassess the complete population for qualification. Its
host-selected authority checker and exact source are bound into the selection. Its retained
decision names this population, authority, rights, source-family development/qualification
split, all three adopters' coverage and limitations. Per-case qualification rights and held-out
exposure, explicit exposure history and training-provenance disclosure are required.

The checker verifies its custodian's actual authority/provenance contract; a nonempty issuer
string or agreement between models does not authenticate reference truth. The host must
establish that contract independently. No real population-review approval is supplied here.
Disclosed uncertainty about pretraining remains uncertainty; it is distinct from missing
exposure facts or known fitting to the qualification cases. No guaranteed-clean pretraining
claim is required or manufactured.

`held_development_trace` is an explicit reporting path for already exposed historical
captures. It preserves proposed labels/bases and every hold reason, but supplies **no checked
reference basis** to evaluation. A right answer is therefore unscoreable, its attributable rate
is null, and the trace cannot qualify even under an explicit TEST_ONLY review. It is not a
shortcut around admission or a new source of labels.

## Host invocation and claims

The protected parent creates `HostInputs` from its source projections and issuer allowlist
before starting the model child. Each record retains canonical input source bytes, version,
hash and actual context. Resolution checks the issuer, input bytes, source identity/hash and
context. The candidate supplies only a subject token to the host; fields in its response or
claim cannot replace those records. Production loaders must derive this context from pinned
repositories/sources, including the real complete candidate universe, rather than asking the
model to declare its own estate or choosing convenient candidates after seeing its output.

`resolver.host_session(inputs).judge(metric, actor_version, subject)` resolves current
permission, then actual host scope, before invoking that exact actor. Refusals retain a counted
subject/reason and human fallback. Successful output gets an opaque receipt retained in the
parent. A model can echo the token; it cannot create the parent-side invocation. Output identity
strings are never used to decide which actor ran.

The existing headline validator obtains the same `Resolver` used by recording and public
verification. On a governed clock it requires `run.host_session` and each claim's
`host_receipt`/`host_subject`. It compares actor, selection, metric, adopter, subject, actual
answer, actual basis, host component and original signal metadata/provenance. It also checks
that the claim file retains the host's counted judgements and declines. Omissions, duplicates,
foreign scope, source changes, receipt replay against another input and forged self-scope
refuse. It retains the existing forbidden override/enactment/price/merge rules.

Clock identity still comes from `derive_clock`: GitHub environment markers overrule a file's
local assertion. Human and local-clock claim semantics remain unchanged. A qualification
permission covers judging only; it never grants merge rights or human overrides.

## Signal input and independent basis assessment

`signal_inputs.resolve_signal_input` constructs the same canonical input for qualification
and live use. Its host caller supplies independently acquired source/party digests, the staged
`ModelRepo` and the declared domain, capability, frame, model date and exact repository pins.
The resolver opens the actual overlay with the party's declared pricing threshold and uses
the existing `ingest.candidates_of` population: all fifteen world and five local definitions,
in their actual order. A changed or dirty closure refuses. The protected context retains the
complete eligible set and its digest; it contains no selected component. Evolution and other
fixed-component judgements still require their original host target.

Only the statement, display source, declared source context, model context and complete
candidate definitions reach the signal actor. Original source bodies remain in host evidence;
the candidate receives their identity/version/byte-count/hash manifest and the declared literal
excerpts. The resolver checks those excerpts against the retained original bytes. It does not
invent a description where a source component has none. Source/task dates and model dates are
separate. The host-authored `signal.from` pin is preserved; an acquisition process must establish
its actual feed membership. A URL or display name cannot establish that fact by itself.

A reviewed signal selection freezes each adopter's exact universe digest, model closure,
model date and input-construction source hash in its population envelope. A self-consistent
new live packet cannot borrow a qualified frame from another closure. The adapter parses a
flat `component` into the existing scorer's `claim.component` without an alias lookup or
incumbent prediction. Before capture, selection checks every actual qualification input's
full universe, model pins/date and construction identity against its adopter's envelope, and
checks its namespace, domain, capability, frame, source family and task date. The same
`binding_context` reader is used by source construction and prompt rendering; changed
definitions or a five-choice substitute refuse before runner invocation. It is not a substitute
for custody's independent byte-for-byte input compatibility receipt. Missing basis remains
missing. Structured quote lists and reasons are retained from actual output; their canonical
JSON representation supplies the existing claim
schema's evidence text. A malformed response, foreign member or absent literal witness is a
counted refusal, never repaired into an answer.

Literal witness checks are necessary but insufficient. `BasisPolicy` freezes the independent
review rubric, registered acquisition issuers and policy source. After capture, a review
request discloses actual raw output, answer, basis, original input, original sources and host
context. It omits hidden expected answers and reference bases. The protected parent acquires
review records through a `ReviewStore` whose exact digest comes from host configuration, not
model output. Every ordered row needs an exact subject digest, original reviewer bytes,
acquisition provenance, and witness/STEEP/binding/applicability dispositions with actual
reasons and source locations. Quotation existence does not author those dispositions. The
reviewer must assess entailment, tense, the selected component's primary subject and applicable
frame; unsupported or uncertain conclusions remain fail or held.

The contextual evaluator preserves RIGHT, WRONG, WRONG_BASIS and UNSCOREABLE. A wrong answer
is still wrong; a correct answer with a failed semantic assessment is wrong-basis, and a held
assessment is unscoreable. Missing, stale, foreign or forged assessments refuse recording or
permission. Assessment identity is conserved through score binding, facts cache, durable
bundle import and the public verifier. These receipts authenticate protected acquisition and
exact subjects; they do not make an untrusted reviewer authoritative by its own declaration.

For a live reviewed signal, the parent retains the actual output as pending and counts the
initial refusal. `review_pending` resumes that exact capture without inference. A passing
independently acquired review can mint a receipt; a failed or held review consumes the pending
attempt and remains in retained outcomes. Declines are never removed from the claim document.
Pending and accepted outputs survive protected catalogue import in a separate process, with
current source, runtime, scope and actual parser agreement checked again.

The existing validator exposes `--run-registered-signals ADOPTER --output NEW_DIRECTORY`.
It loads jobs, source/party pins and review acquisition only from its protected judge catalogue,
checks current permission, invokes the shared input/actor/session path, and writes a claim only
after the existing validator accepts it. The command can also resume a protected pending
session. No claim-selected catalogue, reviewer path or TEST_ONLY override is exposed. Existing
claim-file validation remains available, and this command does not start a schedule or merge
anything. An existing output directory refuses to preserve historical evidence.

`signal_candidate.freeze_actor` binds the input adapter, parser, prompt, serializer, reviewed
basis policy and a pinned host backend/executable. One immutable config is used for invocation
and provenance. The subprocess transport runs a tokenizer-only preflight before generation,
refuses over-bound inputs without truncation, applies a shared timeout and compute-thread
environment, and retains raw output with host observations even on output-limit failure. The
backend must independently observe its actual loaded assets/build/dtype/device and resource
and cage facts. Model-response identity fields are never used as runtime observations.

No real model backend, Linux network cage, reviewer acquisition, current qualification
population or signal job is registered by this source change. The proposed Linux BF16 profile
and 4096/512 caps remain unmeasured. Controlled Python subprocesses and authored TEST_ONLY
assessment receipts prove software mechanics only; no actual model load, tokenization or
inference is part of these tests. Current custody/input compatibility, independently reviewed
backend/cage acquisition, bounded target measurement, actual complete capture and semantic
review, all ten permission conditions and an observed operational outcome remain prerequisites.
The historical Mac smoke and its caps/measurements remain unchanged.

## Durable verification and the trust assumption

Fresh captures carry an ephemeral parent-process authenticator. It is not a durable credential
and is never exported. An exported selection/capture bundle or session archive is **evidence,
not authority by itself**. Later import requires its exact digest to be independently pinned
in the protected, reviewed host catalogue. Import verifies the catalogue pin, rejects escaping
paths/symlinks and changed bundles, resolves current adapters, verifies source/runtime/capture
bindings and only then rebinds the capture to the new host process. Session restore performs
no inference. A separate-process test exercises that complete lifecycle.

`Resolver.from_checkout()` loads the catalogue beside the protected judge package. The normal
validator CLI exposes no model-selectable catalogue path, digest or TEST_ONLY switch. A
protected parent can instead pass its already running resolver to `permission_rules` before
starting its child. The local clock already judges from its pre-child copy; a model-written
repository file is not the source of that copy's authority. The public verifier uses the same
resolver for operational score rows and at-rest governed claims. Its old numerical controls
are labelled historical arithmetic controls, and its registered TEST_ONLY host lifecycle is
tested separately.

This is the existing trusted-host/source separation, not an OS sandbox for arbitrary hostile
Python adapters. Someone who controls the protected host code, catalogue anchor or parent
process can fabricate evidence and is outside this guarantee. A root-looking path, writable
JSON document or its self-reported checksum does not establish that separation. Publication
of a genuine registration still requires ordinary reviewed source/evidence delivery.

## The actual retained smoke

The replay command requires the host-held evidence-manifest pin and verifies the exact
original producer source, input, proposed-reference corpus, raw output and model/runtime
receipt bindings. It keeps the Mac float32 generator distinct from the current replay/parser
composite. It retains original free-text reasoning and observer limitations without making
semantic witnesses from the proposed answer. Its single exposed unreviewed development row
cannot establish an independent population, actual basis fitness, target Linux behaviour or
any earned permission. Replaying those bytes is not another inference.
